# 每日开发交接文档生成

## Role
你现在的身份是【全栈核心开发】。即将结束今天的工作，需要生成一份专业的【每日开发交接文档 (Daily Handover Report)】，以便第二天自己或同事能无缝衔接工作。

## Context
请分析我们今天的完整对话历史、代码变更（Diff）以及**当前最后停留的问题状态**。

## Workflow (执行流程)

### Step 1: 确定文件路径与命名
1. 扫描目录：`docs/handover/`
2. 检测文件名：基于今日日期 (YYYYMMDD) 和目录中已有的最大序号，生成自增序号
3. 命名格式：`{YYYYMMDD}_{自增序号}_Handover.md`
   - *示例*：`20260117_03_Handover.md`
4.存入目录：`docs/handover/`

### Step 2: 撰写交接文档
请严格按照以下结构生成 Markdown 内容，**重点在于"未完成"状态的描述**：

---

# 📅 开发交接日报: {日期}

## 1. 今日产出 (Work Completed)
### 1.1 新增/变更功能
- **功能点**：{列出新增的API、页面或组件}
- **改动范围**：{列出核心修改的文件路径}

### 1.2 核心逻辑说明 (Technical Logic)
- {简述今天完成功能的实现思路，例如：引入了 WebSocket 心跳机制，或者修改了 Redis 缓存策略}

## 2. 踩坑与修复 (Pitfalls & Fixes)
- **已解决的 Bug**：{记录今天遇到并修复的问题}
- **技术坑点**：{记录开发中遇到的环境坑或依赖冲突，作为警示}

## 3. 🚨 遗留任务与当前断点 (Pending & Critical)
> **⚠️ 请重点分析当前对话的最后状态**
- **当前未解 Bug**：{请详细描述当前正在排查但尚未解决的 Bug 现象、已尝试的方案以及推测的根因}
  - *示例：用户长连接偶发断开，已排查网络层，怀疑是 Token 续期逻辑问题。*
- **剩余开发任务**：{列出明天需要优先处理的功能模块}

## 4. 后续注意事项 (Handover Notes)
- **规避指南**：接手此任务时，千万不要动哪些代码？要注意哪些配置项？
- **依赖服务**：是否需要联调第三方（如企微接口、云存储）？

---

## 使用说明
在聊天中输入 `/handover-daily` 或 `/handover` 来触发此工作流，系统会自动分析今天的对话历史和代码变更，生成并保存交接文档。
