# PRD 数据表、迁移与权限安全

数据表设计、迁移与权限需在 PRD 中写清粒度、主键、字段含义、变更方式、可执行迁移步骤与回滚策略；权限需覆盖对象级与功能级、审计与敏感数据。

## 何时使用

- 撰写 PRD 中「数据表设计与数据迁移」「权限与角色矩阵」「数据埋点与日志」及迁移/回滚/灰度策略时。
- 评审表结构是否可落地、迁移是否可验证可回滚、权限是否有后端强校验与审计时。

## 数据表设计要点

- 强制写清：主键、索引、字段类型、默认值、约束、审计字段（created_at/updated_at/created_by/updated_by 等）。
- 日志表：先定义记录粒度，再列字段与样例值、枚举 code。

每张表的 PRD 标注模板包含：

- table_name / 业务含义
- 粒度（主键定义）：单字段或复合主键
- 字段清单：中文名、英文名、类型、是否可空、默认值、取值范围、来源、是否敏感/脱敏
- 索引：索引字段、类型、覆盖查询场景
- 约束：唯一、外键、检查约束
- 变更方式：新增表 / 改造表 / 仅新增字段
- 影响面：读写路径、历史数据兼容、回填策略

## 新增表 vs 改造表决策因素对比表

| 决策因素 | 新增表（优先场景） | 改造表（优先场景） | 需要在 PRD 中写清的结论字段 |
|---|---|---|---|
| 业务语义 | 新实体或新日志粒度；旧表语义不匹配 | 仍是同一实体，仅扩字段/扩状态 | “实体边界是否变化” |
| 历史包袱 | 旧表字段/约束不合理，改动风险高 | 旧表已稳定，变更风险可控 | “对存量数据影响评估” |
| 查询性能 | 新读模型/宽表/汇总表；避免复杂 join | 轻度字段扩展即可满足 | “关键查询是否命中索引” |
| 迁移成本 | 需要回填/双写/切流，但可控 | 可能需要锁表/重建索引/停机窗口 | “迁移窗口与回滚策略” |
| 审计与合规 | 新增审计/操作日志需求（建议独立日志表） | 现有审计字段完善即可 | “审计日志是否独立” |
| 权限隔离 | 新表可按租户/业务线隔离 | 旧表混用可能导致越权风险 | “权限隔离方案” |
| 交付节奏 | 快速上线可先新增表旁路 | 小步迭代更适合改造 | “上线节奏与灰度策略” |

## 数据迁移步骤与回滚策略模板（可直接复制到 PRD）

- **迁移目标**：要达到的数据结构/口径
- **前置条件**：DDL 审核、备份策略、灰度开关准备
- **迁移步骤**：
  - Step 1：上线 DDL（新增字段/表）
  - Step 2：历史回填（批任务/限速/校验）
  - Step 3：双写（新旧结构一致性验证）
  - Step 4：读切流（按灰度维度逐步切换）
  - Step 5：收敛与清理（下线旧字段/旧表）
- **一致性校验**：对账口径、抽样比例、误差阈值
- **回滚策略**：开关回退/读回退/写回退/数据修复脚本
- **风险与兜底**：回填失败、延迟、热点、权限错配

说明：功能开关 + 配置文件无需发版，可作为典型兜底策略表述纳入迁移/灰度章节。

|---|---|---|---|---|---|---|---|
| table_x | ... | ... | ... | ... | ... | ... | ... |

### 强制要求

- 回填必须给批次、限速、预计时长、失败重试策略。
- 双写必须给一致性对账口径与误差阈值。
- 回滚必须给“停止写入 -> 回退读取 -> 数据修复”顺序。

## 权限与安全模板

### 权限模型模板（字段）

- **角色（Role）**：名称、描述、上下级关系（可选）
- **资源（Resource）**：页面、按钮、接口、数据对象
- **操作（Action）**：view/list/create/update/delete/export/assign 等
- **数据范围（Scope）**：全部/本人/本店铺/本组织/按条件
- **前后端分工**：前端控制展示与交互；后端必须做最终权限校验（防 BOLA/BFLA）
- **审计日志**：关键操作（登录/登出/保存/结案/权限变更/导出）写入审计表，字段含操作者、时间、对象、动作、结果
- **敏感数据处理**：字段标注“敏感等级/脱敏方式/展示权限”；避免通过错误信息泄露细节（RFC 9457 安全考虑）

### 权限与安全 Checklist

| 检查项 | 通过标准 |
|---|---|
| 是否覆盖对象级与功能级授权 | 列表过滤 + 详情直达 + 写操作均校验 |
| 是否有审计日志计划 | 至少覆盖关键写操作与权限相关操作 |
| 是否标注敏感字段与脱敏规则 | 手机号/证件/密钥等默认脱敏 |
| 是否评估 OWASP API Top 10 风险 | 至少针对 BOLA、鉴权、资源消耗给出控制点 |
