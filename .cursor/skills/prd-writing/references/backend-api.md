# PRD 后端与接口规范

后端实现与接口契约需可生成 OpenAPI、可测试、可落地；PRD 中必须显式标注幂等、权限校验点、错误结构、限流与缓存策略。

## 何时使用

- 撰写 PRD 中「后端功能与实现逻辑」「接口契约与字段定义」时。
- 评审接口是否具备分页/排序/筛选约定、幂等、统一错误结构、权限与限流时。

## 后端职责分解（四层）

- **领域职责**：实体/状态机/规则引擎。
- **应用服务**：编排事务、幂等、权限校验、审计写入。
- **接口层**：REST/GraphQL，入参校验与错误返回。
- **基础设施**：DB/缓存/队列/搜索/限流。

## 接口设计规范基线

- **契约格式**：默认可生成 OpenAPI（OAS）；未指定技术栈时 REST 为默认，GraphQL 可选。
- **分页/排序/筛选**：采用 Google AIP 约定——List 请求含 page_size、page_token，响应含 next_page_token；order_by 支持多字段与 desc 后缀；筛选优先 string filter + 结构化语法（如 AIP-160-like），便于演进。
- **幂等与可重试**：必须显式标注哪些操作可重试、幂等键或 repeatability headers；防短时重复点击导致重复写入，后端需幂等校验。
- **错误码与异常**：对外采用 RFC 9457 Problem Details（type/title/status/detail/instance），避免泄露实现细节或隐私；对内保留稳定业务 error_code 与错误码表、重试建议。
- **性能与限流**：明确 page_size 上限、导出异步化、索引与限流阈值（OWASP API Top 10：Unrestricted Resource Consumption）。
- **权限**：每个接口标注 authz 校验点；对象级/功能级授权在后端强校验（BOLA/BFLA 等）。
- **缓存**：写清缓存键、TTL、失效策略；涉及权限/租户的数据按租户或角色分片缓存。

## 接口设计模板（每接口必填字段）

建议每个接口都输出同样的字段结构，便于 AI 生成 OpenAPI。

- api_id / 名称 / 版本
- 业务目的（与页面/动作绑定）
- 方法与路径（REST）或 Query/Mutation（GraphQL）
- 权限：角色/权限点；对象级校验规则
- 请求参数表：字段、类型、必填、约束、样例、来源（query/body/path/header）
- 响应结构表：字段、类型、含义、样例
- 分页/排序/筛选：字段名、合法白名单、默认值、上限
- 幂等：幂等键/重复请求处理
- 事务：跨表写入一致性
- 错误码：业务错误码表 + HTTP 状态码
- 性能：QPS 预估、索引、缓存、超时
- 观测：日志字段、trace_id/request_id、关键埋点

### 字段清单（完整）

- **api_id / 名称 / 版本**
- **业务目的**：与页面/动作绑定
- **方法与路径**：REST 方法 + 路径，或 GraphQL Query/Mutation
- **权限**：需要的角色/权限点；对象级校验规则
- **请求参数表**：字段、类型、必填、约束、样例、来源（query/body/path/header）
- **响应结构表**：字段、类型、含义、样例
- **分页/排序/筛选**：字段名、合法字段白名单、默认值、上限
- **幂等**：幂等键/重复请求处理
- **事务**：跨表写入的一致性要求
- **错误码**：业务错误码表 + HTTP 状态码
- **性能**：QPS 预估、索引要求、缓存建议、超时建议
- **观测**：日志字段、trace_id/request_id、关键埋点

### 分页/排序/筛选约定（AIP 风格）

- 分页：请求 `page_size`、`page_token`；响应 `next_page_token`；分页时其他参数必须保持一致。
- 排序：`order_by` 支持多字段与 `desc` 后缀。
- 筛选：优先使用 string filter + 结构化语法（如 AIP-160-like），避免为每个筛选需求定制结构体。

### 错误结构（RFC 9457 + 业务码）

- 对外：Problem Details（type, title, status, detail, instance）；不泄露实现细节或隐私。
- 对内：稳定 business error_code、错误码表、重试建议。

### 幂等与可重试

- 显式标注：哪些操作允许重试；幂等键或 repeatability headers（如 Azure REST Guidelines）。
- 业务要求：防短时重复点击；后端幂等校验，重复请求不产生重复写入。

### 性能与限流（OWASP 相关）

- 明确：列表 page_size 上限、导出异步化、查询索引策略、限流阈值。
- 权限：每个接口标注 authz 校验点；对象级/功能级授权后端强校验。

## 改造类需求必填：现有接口盘点（As-Is）

在写新接口前，先盘点存量接口与兼容边界；禁止直接新增接口描述而不说明现状。

### 存量接口盘点模板

| 接口ID | 当前用途 | 调用方 | 当前行为 | 本次改造 | 兼容策略 | 风险等级 | 灰度开关 | 回滚方式 |
|---|---|---|---|---|---|---|---|---|
| API-001 | ... | ... | ... | ... | ... | ... | ... | ... |

### 兼容策略最小要求

- 新增字段：写明默认值与旧客户端兼容行为。
- 修改语义：写明版本策略（v1/v2）或双读双写策略。
- 删除字段：必须给迁移窗口与下线条件。
- 排序/筛选变更：明确是否影响旧查询结果稳定性。

## 权威参考

- RFC 9457 Problem Details for HTTP APIs
- Google AIP-132（List）、AIP-160（Filter）
