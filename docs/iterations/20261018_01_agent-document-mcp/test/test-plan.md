## 故障注入与放行

用可控制屏障在候选生成后、PG COMMIT前后、响应发送前、live apply前、outbox投递后暂停进程；使用子进程终止、网络代理及真实数据库事务锁验证，不mock掉被验证的提交机制。验证COMMIT不明时先获取行锁排除旧事务，再判断是否需重做。对Hocuspocus4固定版本验证beforeSync抛错确实阻止apply、持久化后重复apply无副作用、旧owner不能保存以及pending Yjs structs不丢失。

P0必须通过AC-01～08和18，否则不得开Agent写；P1执行AC-01～20并完成原型/浏览器检查；P2全部24项及14天观察，发布客户端矩阵和开发者说明。任何零泄露、零双写、零重复效果要求均不能用99%成功率抵消。

实现时运行相关仓库守卫：迁移改动执行security:migration-order；编辑栈改动执行guard:prosemirror-singleton及client build并打开真实已有文档；部署/会话设置改动执行guard:realtime-deployment；目录创建改动执行既定tree模型测试、client build及server:build。具体测试命令在实现PR中记录，不将本轮文档检查冒充通过这些运行测试。
