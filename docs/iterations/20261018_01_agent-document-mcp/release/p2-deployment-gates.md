# P2 放行门槛

本轮不部署。P2 准备完成不等于 AC-21～24 全部通过，保持公开放行关闭。

| 验收 | 当前可完成的本地工作 | 必须在部署环境完成 |
|---|---|---|
| AC-21 客户端兼容 | Codex 与独立 MCP SDK 示例的发现→OAuth→工具发现→创建/编辑→撤销；精确版本记录 | 真实 HTTPS 域名、网关、反代、实际回调与浏览器策略下重跑；若支持第二个商业 Agent 产品，必须对该产品单独验证 |
| AC-22 开发者接入 | 文档、可执行示例、参数/错误/配额/留存边界；示例在本地沙箱执行 | 发布真实接入地址及文档 URL，独立开发者按文档完成指定沙箱接入并留下记录 |
| AC-23 停用与运维 | 工作区停写边界、读取/结果保留、故障注入告警判定、只读诊断和运行手册 | 所有真实节点观察相同策略；实际监控调度/通知送达/升级/恢复；真实备份恢复与回退演练；网关超时和负载验收 |
| AC-24 公开放行 | 新 workspace 默认关闭和本地 P1 回归证据可准备 | 连续 14 天试用观察、事故复盘与高严重度缺陷清零、产品/后端/协作/测试/运维签署 |

## 部署后逐项执行（当前全部待执行）

- [ ] 记录实际候选提交/镜像 digest、域名、节点数量、PG/Redis版本及独立 Redis 证明。
- [ ] TLS/反代保持 Host、Authorization、Origin、WWW-Authenticate、MCP 协议头及请求体；OAuth POST 不被改写、缓存或记录秘密。
- [ ] 元数据 issuer/resource 与公网 URL 一致，public/confidential 回调白名单及浏览器 Origin 在真实网络成立。
- [ ] 每节点使用相同的必要密钥和配置，应用角色非 superuser/BYPASSRLS；旧 writer/旧浏览器被正确阻断。
- [ ] 从外部客户端重复完整授权、创建、预览、编辑、幂等、撤销和刷新拒绝；发布经过实际测试的支持矩阵。
- [ ] 独立开发者仅凭公开指南完成沙箱接入；记录遇到的问题和文档修订。
- [ ] 执行关闭写入的多节点竞争，证实关闭先提交零效果、提交先关闭保留结果，读取/历史可用。
- [ ] 注册诊断采样任务、配置通知人和升级路由；注入超时/积压/采集失败，取得实际送达和恢复回执。
- [ ] 一致备份恢复至隔离环境，验证 Y.Doc、journal、版本、历史、操作结果和授权边界；演练兼容回退。
- [ ] 在目标硬件和网络上按 AC-20 重测，记录 P95/P99、事件循环延迟、数据库写放大、锁等待及大文档上限。
- [ ] 完成 14 天观察，每日记录失败/冲突/恢复/配额/延迟/授权问题；不能用本地几十秒测试折算观察天数。
- [ ] 各责任角色签署，所有已识别公开放行前置事项有证据，再另行取得发布授权。

## 不应推给“部署后测试”的事项

以下并非必须上线才能解决，仍需在公开放行前完成：指定实际责任人与试用产品/用户；独立开发者接入记录（也可先在本地沙箱开展）；实际备份窗口、保留名单及用户注销/删除例外政策；需要支持但尚未验证的商业客户端。当前只证明 Codex 和一个独立 SDK 客户端，不泛称所有公开 Agent 可用。

公开开发者自助登记、动态客户端注册、秘密自助轮换没有实现，指南明确采用管理员预登记；需要更换策略时应走后续明确范围的设计/实现，不能临时放开任意回调或客户端自动注册。

清理与监控工程前置项已补齐，证据见 [本地报告](../test/p2-retention-observability.md)。部署后还须验证每节点采集、实际清理规模/锁等待/WAL、保留名单一致性，以及启用清理后的备份恢复和兼容回退。
