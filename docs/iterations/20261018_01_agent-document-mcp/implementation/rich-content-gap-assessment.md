# MCP 富文档能力差距评估

用户要求：文章全文导入须保留表格、图片等文档结构，并盘点 Mermaid、分割线及已有编辑器功能的 MCP 支持；暂停原合并、部署和降级导入路径。用户已确认拥有转载授权。

| 引用 | 24 个 blockquote | 保留引用结构 |
| 列表 | 11 个无序列表、3 个有序列表，共 55 个 li | 保留嵌套、顺序与编号 |
| 行内代码 | 3 个 code | 保留代码标记 |

## 现有能力矩阵

这里区分网页编辑器与 MCP 创建/编辑；读取能返回 HTML/Markdown，不等于对应节点可由 MCP 写回。

| 能力 | 网页编辑器 | MCP 当前创建/编辑 | 缺口 |
|---|---|---|---|
| 段落、标题、引用、普通列表、代码、基础标记、链接 | 已有 | 基本支持 | 继续覆盖往返和嵌套验证 |
| 表格 | 已有 | 拒绝 | 表头、单元格及结构化读写；复杂表格后续覆盖合并、对齐、宽度 |
| 图片/GIF | 已有 | 拒绝；无附件上传/导入工具 | 附件传输、引用、尺寸、图注、错误恢复及权限 |
| 分割线 | 已有 | 拒绝，包括 --- 和 *** | 支持 horizontalRule 创建、定位和编辑 |
| Mermaid | 已有渲染 | 探针确认 mermaid fenced code 可转换并原样读回 | 补 MCP→持久化→真实页面渲染→再次编辑验收及语法错误反馈 |
| 待办列表 | 已有 | 拒绝 | taskList/taskItem 与勾选状态 |
| 数学公式 | 已有 | 拒绝 | 行内/块级公式及源码往返 |
| 提示块、折叠块 | 已有 | 不支持原生节点 | 类型、标题和子块内容；不能当普通引用处理 |
| 高亮、文字颜色、上下标、对齐等 | 已有 | 不能完整表达；复杂标记保护整块 | 受控属性/标记读写及保留规则 |
| 视频、音频、PDF、文件 | 已有 | 无对应写入工具 | 复用附件基础能力并定义各节点行为 |
| Draw.io、Excalidraw | 已有 | 原生节点受保护 | 源数据、附件与预览版本保持一致 |
| 分栏、分页、状态、提及、子页面、同步块、嵌入 | 已有 | 专有节点受保护 | 按节点协议接入，保留引用对象和权限关系 |

已运行转换探针：表格、图片、分割线、待办、数学、折叠 HTML 被拒绝；Mermaid/普通代码/引用接受。`==重点==` 被接受为普通文字而非高亮；GitHub 风格 `[!NOTE]` 被接受为普通引用而非本系统原生提示块。它们不能算作对应功能已支持。

## 根因与接口边界

- `apps/server/src/core/mcp/markdown-content.ts` 限制 Markdown 子集，并在解析后验证节点。
- `apps/server/src/core/document-command/document-candidate.ts` 的 `isEditableBlock` 仅放行少量文本节点与标记；受保护子节点会保护整个祖先块。
- `apps/server/src/core/mcp/document-tools.service.ts` 只接受 append、prepend、replace_block；编辑上下文主要提供字符串化块内容，单块文本有 8000 字符上限。
- 普通 fetch 基于 materialized content，有截断预算；它不是无损编辑快照。富内容编辑必须沿用基于 Y.Doc 的版本上下文。
- 图片读取已经支持附件元数据、链接和部分小图内联，但没有对称的图片写入通道。

不能只删除正则限制或扩大节点白名单。需要校验每种节点的属性、子结构与附件引用，并保持版本冲突、ACL、幂等、历史和 Y.Doc 原子持久化。

## 变更影响

| 领域 | 影响/处理 |
|---|---|
| 类型 | cross_surface_change：从文本子集写入扩展为原生富文档读写 |
| 业务对象 | modify：文档节点与附件关系；新增导入资源清单/映射概念，复用既有附件存储 |
| 主流程 | modify：原文提取 → 元素与资源盘点 → 附件准备 → 富节点转换 → 预览核对 → 提交 → 读回与浏览器验收 |
| 新增页面 | 暂不要求新路由；优先使用现有文档页、连接管理与历史页 |
| 修改页面 | modify：MCP 设置说明/能力列表；文档页复用原生节点展示 |
| 删除/降级 | legacy：将表格转列表、图片转链接、分割线删除的临时导入方案，不作为默认成功路径 |
| 状态 | add：资源准备中、部分资源失败、暂存、可重试、已提交及恢复核对 |
| 入口/返回 | modify：导入失败可按原操作重试；完成返回实际文档链接 |
| CTA/文案 | modify：不能把请求接受或正文写入表述为完整导入；明确遗漏或不支持元素 |
| 可见数据 | add：元素计数、资源成功/失败数、来源信息、转换差异 |
| 组件 | unchanged 为主：复用表格、图片、Mermaid 等组件；新增 imageFigure/imageCaption 共用扩展，保持图片与可编辑图注关系 |
| 接口 | modify：结构化节点输入/输出及块内定位；add：资源传输/导入、能力发现；精确工具名待接口设计 |
| 权限 | preserve：OAuth scope、空间/页面 ACL；明确新附件操作的授权与额度，不复用管理员绕过 |
| 文档合同 | modify：现有只支持文本子集的 PRD/SDD、public 指南、兼容矩阵、设置页与验收清单 |
| 验收 | add：本文 2 表/15 图/14 线完整性；GIF、图注、刷新/协作/历史；Mermaid 渲染与编辑；失败重试不重复 |
| 发布 | 原 PR 保持未合并；先完成新范围设计和验证，再决定同 PR 扩展或拆分后发布 |

## 建议实施顺序

1. 本次必需：原生表格、图片/GIF附件、图注、分割线、标题/列表/引用结构保真与来源记录；补 Mermaid 端到端验证。
2. 共用基础：受控结构化内容输入、结构化编辑上下文、能力发现，以及资源暂存/绑定/重试和遗漏报告。继续使用既有 Tiptap/Yjs/Hocuspocus，不引入第二套编辑或同步后端。
3. 后续完整对齐：待办、提示/折叠、公式、必要文字样式，再接视频/PDF/附件、绘图源数据、分栏/同步引用/嵌入。
4. 编辑粒度：支持在指定块前后插入、删除/移动块、修改表格单元格、替换图片、更新 Mermaid 源码；避免修改局部内容时整页重写。

图片应存为 Docmost 附件，不能以外链可打开代替导入成功。下载能力应限制协议/地址、验证实际文件格式/大小，并校验附件归属；失败应可重试且不能产生重复页面或无主附件。

本次文章没有 Mermaid 源码，默认保留原图。若另行要求转成可编辑 Mermaid，应作为基于原图重建的独立动作，保留来源和验证，不能与忠实导入混同。
