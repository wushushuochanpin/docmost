# Book SDD：采用统一认证 SDK

## 现状和改造边界

`IdentityService` 当前直接通过 `IdentityProvider` 处理中心托管事务、OIDC code/PKCE、签名验证及中心状态；依赖 Book 自己的事务库、浏览器 handle、本地 session 和账号关联。Book 没有现有公司 Node SDK 依赖，因此是首次接入并逐步替换重叠认证逻辑，不是简单升级依赖。

## 目标设计

- 固定安装中心交付的私有 Node SDK；以 NestJS 适配器接入其认证核心与明确重新认证 API；先验证 SDK 不强制 Prism grants、SQLite 或产品会话模型。若合同不满足先回中心修 SDK，不绕过准入。
- 保留 Book 工作区、issuer、subject → user 的绑定与唯一性检查；保留用户有效状态、邀请、密码验证、MFA、会话、文档与权限。中心身份只可用于本产品既有准入。
- 用户显式切换时调用 SDK 发起新事务；默认普通入口仍复用 SSO。前端清晰说明原账号登录/绑定和重新认证；保持返回路径白名单，无错误重试循环。
- SDK 与 Book 共同约定事务状态、浏览器绑定、单次消费、密钥保管、回调和已验证 auth_time 的责任；禁止两套并行认证实现争夺同一回调或互相放宽检查。以适配层/受控开关分阶段替换，迁移中旧在途事务有明确完成或安全过期策略。
- 维持本地会话与中心失效/暂时不可用的既有合同，以及多标签、退出与长连接行为；不改变既有关联记录。自动化使用隔离数据库与模拟提供方，真人扫码单列。

## 发布与回退

核验 GitHub Packages 可见性、Book CI 安装权限、包版本与摘要后提交固定依赖和 lockfile；凭据只放受控 secret。评估切换中的在途事务和会话兼容，以功能开关/上一制品回退；先备份并验证原数据，避免清理业务数据。部署须按 Book 发布规则和明确授权执行。

## 共同验收与依赖

| ID | 场景与结果 |
|---|---|
| ACC-IDC-SW-001 | 普通登录允许复用有效中心会话；无会话进入中心可用登录方式。 |
| ACC-IDC-SW-002 | 未关联或本地用户不可用时安全拒绝，提供明确恢复入口；不得自动建用户、按邮箱/昵称合并或扩大权限。 |
| ACC-IDC-SW-003 | 用户主动切换账号，创建新事务并要求重新认证；旧中心会话不能直接完成此事务，不全局退出其他产品。 |
| ACC-IDC-SW-004 | 新身份关联且用户可用才建立 Book 会话；仍不匹配时可恢复，不自动重试循环。 |
| ACC-IDC-SW-005 | 过期、取消、重放、篡改、并发标签、中心不可用、旧回调和浏览器会话变化均安全处理；保留草稿与业务数据。 |
| ACC-IDC-SW-006 | 准确区分自动化替身、真实中心、真人微信扫码和线上验收；检查既有关联、成员、文档、权限与现有产品会话。 |
| ACC-IDC-SW-007 | 发布制品可追溯、私有包读取授权最小化、固定版本及 lockfile，回退可操作。 |
