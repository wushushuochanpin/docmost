# PRD：Agent 连接和权限管理

状态：draft；本轮用户明确要求同时产出 PRD+SDD，细化方案供审阅，非已上线事实。目标是让豆包工作、Codex 及兼容 MCP 的 Agent 在明确许可下读取与编辑；令牌与 OAuth 两种方式都能创建、查看、修改、撤销。保持 Node 22、现有 Tiptap/Yjs/Hocuspocus 和 Y.Doc 写入权威。

## 已知事实
豆包 HTTP + API 令牌已实测 search/fetch；旧令牌四工具只读。豆包无凭据访问线上 OAuth 失败，但模拟服务公布注册端点时豆包请求动态注册并显示待授权，根因需真实端到端确认。Codex 预登记 OAuth 在隔离环境完成读取/创建/编辑；不是线上长期连接验收。

## 范围与规则
- OAuth：支持标准公开客户端动态注册；仅登记客户端信息，不授予任何用户数据。用户登录授权页选择空间、只读/创建文件夹/创建文档/编辑，确认后回客户端。至少 knowledge.read 才能使用写权限。默认只读；客户端未请求的权限不能被授权；工作区禁写时写项禁用并解释。
- API：创建个人 MCP 专用令牌时选择名称、空间、权限和到期时间；默认只读。令牌明文只显示一次，关闭后不能再取回；遗失则创建新令牌并撤销旧令牌。新令牌的写能力仅对 MCP 生效，不扩大其他 HTTP API 权限。既有令牌维持原来 HTTP 能力与 MCP 只读行为，绝不自动升级。
- 管理：展示名称、类型、空间、授权权限、有效期、创建/最近使用时间、状态；个人可管理自己的连接；管理员仅按现有角色管理工作区范围，不暴露明文。提供缩权、增加权限、撤销；变更前展示差异。API 升权由有权限用户在已登录页面明确确认；OAuth 升权必须客户端发起新的授权申请，用户重新确认，原授权在新授权成功前不扩大。若客户端不支持增量授权，告知重新连接，不伪装成功。
- 缩权、撤销生效边界：最终提交前由同一事务中的授权屏障判定；变更先于屏障则拒绝且不留写入，写入先于屏障则可能完成并可审计。已返回给 Agent 的内容无法收回。
- 本期不新增删除/移动文档、自动批准授权、通用第三方应用商店或第二套编辑/协作后端。注册应用展示为未验证客户端；名称不可证明品牌身份。

## 主流程和异常
1. 用户在 Agent 输入地址，客户端自动注册，点授权；浏览器登录后选择空间与权限、确认；成功返回客户端，用户可从连接列表管理。拒绝/取消回客户端不创建授权，过期或错误提示重新开始。回调失败时允许返回连接管理检查状态和重试，不重复授权。
2. 用户进入令牌管理→创建→填名称/到期/空间/权限→确认→一次显示和复制→返回列表。保存中禁重复提交；取消无凭据；失败保留输入并重试；复制失败手动选择复制。过期、撤销状态禁止编辑权限，需新建。
3. 管理列表选择连接→查看详情→缩权或升权确认→成功刷新；版本冲突刷新后重试；无权限/禁写解释原因；网络超时读取结果确认，不盲目重复。撤销需确认，成功后显示已撤销；重复撤销幂等。列表加载失败可重试，空列表提供创建入口。

## 验收
- AC01：豆包真实客户端动态注册→授权→发现工具→读取与编辑→读回；只读不出现写工具；记录客户端精确版本及网络环境。
- AC02：Codex 预登记路径不回归；测试 OAuth 授权、发现、编辑、撤销；能否动态注册须独立实测。
- AC03：API 新建只读/指定空间写入、一次展示、列表、缩权、用户明确升权、撤销和过期；旧令牌保持只读且原接口不变。
- AC04：OAuth 初始授权、取消拒绝、缩权、重新授权升权、撤销和刷新/重放处理；无额外权限。
- AC05：任何调用及最终提交执行实时 ACL、范围、用户状态、工作区策略、凭据状态；跨工作区和猜 ID 均拒绝。
- AC06：人机互斥、版本冲突、幂等、崩溃恢复、Y.Doc 持久化和历史审计不回归；禁止直接写 pages.content。
- AC07：动态注册滥用受限；严格回调、PKCE、资源绑定、防重放、日志不泄密；注册本身不读写文档。
- AC08：受控灰度与回退、数据库迁移、真实备份恢复以及线上同一候选身份验证完成。
