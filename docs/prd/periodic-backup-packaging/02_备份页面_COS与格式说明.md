## 1. 页面功能概览

在 **设置 → 系统 → 备份与恢复**（仅自托管 Admin 可见）提供：

| 能力 | 说明 |
|------|------|
| **定时备份** | 按策略（Cron 或预设：每日/每周）自动执行，结果上传到配置的目标（本地或腾讯 COS）。 |
| **一键备份** | 点击「立即备份」触发一次**全量**备份，同上传到当前配置目标（含腾讯 COS）；触发者记为当前登录账户。 |
| **上传到腾讯 COS** | 项目已通过 S3 兼容接口对接腾讯 COS（`AWS_S3_*` / endpoint 指向 COS）。备份产物上传到配置的 bucket/prefix，无需额外对接。 |
| **下载到本地** | 任务列表中**成功**的备份提供「下载」：后端生成短时效签名 URL（本地存储则直接可读路径或临时 HTTP），用户浏览器可下载到本地。 |

### 1.1 备份任务列表（异步 + 状态机 + 触发归属）

- **异步执行**：手工或系统触发后接口立即返回，任务在后台执行；列表需展示**状态机**中的全部状态（见 PRD 5.4）：**等待中**、**备份中**、成功、失败、已取消。触发后新任务以「等待中」出现，随后变为「备份中」→ 终态；建议轮询或 WebSocket 刷新以看到「备份中」等中间状态。
- **展示内容**：所有备份任务按时间倒序，每条至少包含：
  - **备份时间**：开始时间、结束时间（或耗时）；进行中时仅开始时间；
  - **文件大小**：成功时显示产物大小，否则可为「—」；
  - **状态**：**等待中** / **备份中** / 成功 / 失败 / 已取消；失败时展示错误摘要；
  - **触发方式**：**手动触发** → 展示**操作人**（当前登录账户）；**系统定时触发** → 展示「**系统**」；
  - **操作**：下载（仅成功）、恢复（含 dry-run）等；进行中可提供取消（可选）。
- **触发归属约定**：与 PRD 5.5 一致；后端存储 `triggerType`（schedule | manual）及手动时的 `triggeredByUserId`，用于展示与审计。

实现要点：

- 复用现有 **StorageService**（S3 驱动）与 **EnvironmentService**（`AWS_S3_*`）配置，备份目标选择「S3/COS」时使用同一套密钥与 Bucket，仅 prefix 使用独立目录（如 `backups/`）。
- 前端：备份策略表单（周期、保留策略、目标类型、COS prefix）、任务列表（上述字段）、「立即备份」按钮。
- **每次备份一个包**，任选一份即可单独还原，无依赖链。

## 2. 备份格式与第三方打开方式

### 2.1 整体包格式

- **推荐**：`backup-<workspaceId>-<yyyyMMddHHmmss>.tar.zst`  
  - 标准 **tar** 打包 + **zstd** 压缩，任何支持 tar + zstd 的工具均可解压（如 `tar -I zstd -xf xxx.tar.zst`，或 7-Zip、Ark 等）。
- **兼容回退**：可配置为 `tar.gz`，便于在无 zstd 的环境下用 gzip 解压。

### 2.2 包内结构（与 TECH-SPEC 一致）

```text
manifest.json          # 元数据：版本、时间、workspaceId、清单、checksum 等
db/
  docmost.sql.gz       # 数据库逻辑备份（见下）
storage/               # 文件存储快照（与当前 STORAGE_DRIVER 一致）
  ...
checksums/
  SHA256SUMS
meta/
  version.txt
```

### 2.3 数据库备份格式：Plain SQL（.sql.gz）

- **格式**：PostgreSQL **plain SQL** 导出后 gzip 压缩，即 `docmost.sql.gz`。  
  - 导出方式等价于：`pg_dump -U user --no-owner --no-acl -Fp docmost | gzip`（`-Fp` = plain 文本）。
- **用其他方式是否可正常打开**：**可以。**
  - **解压**：`gunzip docmost.sql.gz` 得到 `docmost.sql`。
  - **查看/编辑**：任意文本编辑器均可打开；可用 `psql -f docmost.sql` 导入任意兼容版本的 PostgreSQL；也可用 DBeaver、pgAdmin、DataGrip 等执行其中 SQL。
  - 与自定义格式（`pg_dump -Fc`）相比：plain SQL 可读、可跨库/跨版本导入，便于审计和应急手工恢复；体积略大，但经 gzip 后通常可接受。

### 2.4 小结

| 内容 | 格式 | 第三方打开方式 |
|------|------|----------------|
| 整体包 | `.tar.zst`（或 `.tar.gz`） | 解压：`tar -I zstd -xf` 或 7-Zip/Ark 等 |
| 数据库 | `db/docmost.sql.gz`（plain SQL） | `gunzip` 后用文本编辑器/`psql`/任意 PG 客户端 |
| 文件 | `storage/` 下普通文件 | 解压后直接访问目录与文件 |
| 元数据 | `manifest.json`（JSON） | 任意文本编辑器或脚本解析 |

## 3. 与现有 PRD/TECH-SPEC 的对应关系

- **策略与调度、权限、审计、恢复流程**：见 [PRD.md](./PRD.md)、[TECH-SPEC.md](./TECH-SPEC.md)。
- **腾讯 COS**：使用现有 S3 兼容配置，备份目标选 S3 时 endpoint 指向 COS 即可；本补充文档明确「页面上一键备份 + 定时备份均支持上传到 COS」及「下载到本地」。
- **恢复时选择备份**：支持**从任务列表选择**、**从 COS 自动拉取备份记录并手工选择**、**上传备份包后手工选择**三种方式之一进行还原，需明确选定一份后再二次确认（见 PRD 5.6、TECH-SPEC 6.2 与 API 草案）。
- **格式**：TECH-SPEC 中 DB 建议采用 **plain SQL（.sql.gz）**，便于通用工具打开；本补充文档作为产品侧对「备份是什么格式、其他方式能否打开」的正式说明。
