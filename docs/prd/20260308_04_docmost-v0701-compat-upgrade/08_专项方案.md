## 冲突热点清单

| 热点文件/目录 | 本地语义 | 上游语义 | 处理建议 |
| --- | --- | --- | --- |
| `apps/client/src/App.tsx` | 主题、路由、分享入口、本地页面壳 | 新增 audit/MCP/AI 等路由 | 以本地 App 为准，逐个补路由 |
| `apps/client/src/features/editor/page-editor.tsx` | 本地工具栏与字号偏好 | 上游 editor refresh/status/attachment paste | 逐块合并，不接受整文件覆盖 |
| `apps/client/src/features/page/tree/components/space-tree.tsx` | folder-first、统计、粘性工具栏 | permissions/search/sort | 先保留本地树，再接功能点 |
| `apps/server/src/core/page/services/page.service.ts` | 本地 shared DB/RLS/page 规则 | page content API、permissions、audit 触发 | 需要手工重构式合并 |
| `apps/server/src/core/share/share.service.ts` | 本地分享 SSR/static/微信链路 | 上游 share 相关修复 | 本地为主，上游补丁为辅 |
| `apps/server/src/integrations/environment/environment.validation.ts` | 微信/备份变量 | ClickHouse/event store 变量 | 合并校验模型，不删本地字段 |

## 推荐执行顺序

1. 先处理部署/环境/依赖，保证可编译。
2. 再处理数据库迁移和类型生成。
3. 然后处理 editor、page/tree、settings、workspace 管理等上游功能。
4. 最后处理 page permissions、audit、MCP、AI menu 等高风险 gated 功能。
5. share 和 backup 始终按保护域策略单独回归。

## 专项结论

1. 本次升级可以做，但只能按“保护域 + 选择性并入 + 分阶段 gating”来做。
2. 真正低风险可直接吸收的是 `v0.70.1` 媒体相关补丁、status node、部分列表搜索/排序。
3. 真正高风险的是 editor refresh、page permissions、audit、MCP、page service 与 migration 整合。
