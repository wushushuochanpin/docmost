本文档用于定义实施波次、测试清单、发布步骤与回滚方案。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

## 实施波次

| 波次 | 目标 | 主要动作 | 产出 |
| --- | --- | --- | --- |
| Wave 0 | 锁定基线 | 打 tag、创建升级分支、记录当前环境变量和部署方式 | 可回退基线 |
| Wave 1 | 合入官方基线 | merge `v0.70.1`、处理基础依赖冲突 | 编译前代码面 |
| Wave 2 | 保护本地能力 | 恢复 share/backup/RLS/theme/editor 等保护域 | 本地能力不回退的候选代码 |
| Wave 3 | 并入上游功能 | notifications、editor refresh、status、comments、member 管理增强 | 上游功能可测试 |
| Wave 4 | 整合迁移与类型 | migration、db types、entity types、环境变量整合 | staging 包 |
| Wave 5 | staging 回归 | 执行迁移、接口联调、功能回归、安全验收 | release candidate |
| Wave 6 | 发布与灰度 | test 环境、生产小流量、全量 | 正式版本 |

## 测试范围

### 本地能力回归

1. folder-first 页面树、侧栏统计、粘性工具栏。
2. 登录 return URL 跳回。
3. 页面头、编辑器字号和视图偏好。
4. 深色主题与布局壳。
5. Mermaid 预览。
6. 分享页 TOC、static renderer、密码过期、微信分享。
7. 备份作业列表、刷新、下载、备份域基础流程。

### 上游能力验收

1. Notifications / watchers。
2. Editor refresh / columns / status / paste / media resize。
3. Comments enhance。
4. User deactivation。
5. Spaces and groups search / lists sorting。
6. Page permissions / audit / MCP / AI menu / API key restriction 的 gating 行为。

## 发布计划

| 步骤 | 环境 | 发布内容 | 通过条件 |
| --- | --- | --- | --- |
| R1 | 开发环境 | 编译通过版本 | 本地 smoke test 通过 |
| R2 | `book-test` / staging | 全量功能 + migration | 产品/测试签字 |
| R3 | 生产小流量或低峰时段 | 主版本发布，EE 功能按 gate 控制 | 监控稳定、公开分享正常 |
| R4 | 生产全量 | 完整切换 | 24h 内无严重告警 |

## 灰度策略

1. 先环境灰度，不做功能全量切换。
2. 对高风险模块优先采用“入口隐藏/功能关闭”的灰度方式。
3. 分享和备份域不做行为重构式灰度，要求一次保持兼容。

## 回滚方案

### 触发条件

1. 公开分享页不可用。
2. 编辑器主链路损坏。
3. 备份域不可用。
4. 权限越权或成员管理异常。
5. 生产启动失败或 enterprise 模块加载异常。

### 回滚步骤

1. 关闭新增入口或 feature gate。
2. 回滚部署版本到 `before-upgrade-20260308-main` 对应镜像/tag。
3. 若数据库仅执行加法迁移，则保持表结构不动，应用回退即可。
4. 若出现必须补救的数据问题，由 DBA 依据 staging 演练记录执行受控处理。

### 回滚目标

- RTO：`<= 30 min`
- RPO：不接受功能升级导致的业务数据丢失
