# 02 技术方案：升级分支、模块并入与接口契约

**成文日期**：2026-03-08 20:57:06 UTC+8
**最后修订**：2026-03-08 20:58:36 UTC+8

本文档用于定义技术架构、接口契约与兼容策略。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## 核心技术原则

1. 以当前 `main@069db98b` 为升级底座，新建 `upgrade/v0.70.1-compat`。
2. 通过 `git merge v0.70.1` 吸收官方基线，不用覆盖拷贝方式升级。
3. 把“保护域文件”与“可直接并入域文件”分开处理。
4. 所有高风险域在 build green 之前不允许直接 push 到业务主线。
5. 所有上游 `feat(ee)` 功能必须同时设计 UI gating 和 server/module gating。

## 升级分支与交付流

| 阶段 | 分支/动作 | 产物 |
| --- | --- | --- |
| S0 | `git tag before-upgrade-20260308-main` | 回滚锚点 |
| S1 | `git switch -c upgrade/v0.70.1-compat` | 升级工作分支 |
| S2 | `git merge v0.70.1` | 初始冲突面 |
| S3 | 保护域手工恢复、本地语义回填 | 代码可编译 |
| S4 | 迁移整合、接口联调、回归 | staging 候选版本 |
| S5 | test/prod 灰度与发布 | 正式版本 |

## 保护域与并入域

### A. 保护域

| 领域 | 关键文件/目录 | 处理原则 |
| --- | --- | --- |
| 分享 | `apps/client/src/features/share/*`、`apps/server/src/core/share/*`、`apps/client/src/pages/share/*` | 以本地语义为准，逐条吸收上游 bugfix，不接受整段替换 |
| 备份 | `apps/client/src/features/backup/*`、`apps/server/src/integrations/backup/*` | 无上游等价能力，整体保留 |
| 环境与部署 | `.env.example`、`docker-compose.yml`、`Dockerfile`、`apps/client/vite.config.ts` | 以本地部署模型为准，增量合并缺失变量 |
| 多租户/RLS | `apps/server/src/core/page/*`、`apps/server/src/database/migrations/*` | 不回退本地隔离语义 |
| 主题与站点壳 | `apps/client/src/theme.ts`、`apps/client/src/App.tsx`、全局 layout | 保留本地品牌与主题行为 |

### B. 可并入域

| 领域 | 关键文件/目录 | 处理原则 |
| --- | --- | --- |
| 通知 | `apps/client/src/features/notification/*`、`apps/server/src/core/notification/*` | 直接并入后再按 UI 适配 |
| 状态节点 | `apps/client/src/features/editor/components/status/*`、`packages/editor-ext/src/lib/status.ts` | 直接并入，配合本地工具栏适配 |
| 用户停用 | `apps/server/src/core/workspace/*`、成员管理 UI | 以官方实现为底，补本地交互 |
| 空间/组搜索与排序 | `space-list.tsx`、`group-list.tsx`、repo 排序 | 直接并入，保持本地样式 |

## 模块级并入策略

| 模块 | 主要文件 | 并入方式 | 备注 |
| --- | --- | --- | --- |
| Editor refresh | `apps/client/src/features/editor/*`、`packages/editor-ext/*` | selective merge | 需要保留本地字号/工具栏/Mermaid |
| Page content API | `apps/server/src/core/page/*` | manual merge | 需兼容本地 shared DB/RLS 逻辑 |
| Notifications | `core/notification`、`watcher` | additive merge | 与本地 share/backup 基本解耦 |
| Page permissions | `ee/page-permission/*`、`page-access.service.ts` | gated merge | 与 folder-first 和 RLS 联动验证 |
| Audit logs | `ee/audit/*`、`integrations/audit/*` | gated merge | 先代码并入、后决定是否开放入口 |
| MCP | `ee/ai/components/mcp-settings.tsx` | gated merge | 需确认 enterprise 模块与配置模型 |
| AI menu | `ee/ai/components/editor/ai-menu/*` | gated merge | 不阻断主线升级 |
| Share fixes | `shared-page.tsx`、share controller/service | cherry-pick into local implementation | 以本地分享栈为准 |
| Backup | `integrations/backup/*` | protect | 仅处理与依赖、环境、迁移的兼容关系 |

## 接口契约与 API 处理原则

### 1. Page Content API

| 项 | 方案 |
| --- | --- |
| 上游能力 | 新增页面内容获取/更新接口 |
| 本地兼容要求 | 不破坏本地页面、分享静态渲染、RLS 与 folder-first 语义 |
| 处理方式 | 先引入 DTO/Service 结构，再把本地 page service 逻辑并入 |
| 验收 | 编辑页读写、分享页静态渲染、权限校验均通过 |

### 2. Notifications / Watchers API

| 项 | 方案 |
| --- | --- |
| 上游能力 | 通知列表、已读、watcher、邮件通知 |
| 本地兼容要求 | 不影响本地评论/分享/备份流程 |
| 处理方式 | 先并入后端模块和前端列表，再补与本地 websocket/query 的适配 |
| 验收 | 评论/提及触发通知，通知列表可见，未引入多余 side effect |

### 3. Page-level Permissions API

| 项 | 方案 |
| --- | --- |
| 上游能力 | 页面级授权与发布配置 |
| 本地兼容要求 | 不破坏 folder-first 树、现有 share 模型、RLS 约束 |
| 处理方式 | 代码并入 + UI 入口 gating；默认 staging 验证，prod 视验证结论开放 |
| 验收 | 未开启时不影响现有权限；开启后页面授权正确拦截 |

### 4. Audit / MCP / AI / API Key Restriction

| 项 | 方案 |
| --- | --- |
| 上游能力 | 全部位于 `ee` 路径或依赖 enterprise 模块 |
| 本地兼容要求 | 不出现“入口可见但后端未授权”或“模块加载失败导致启动异常” |
| 处理方式 | 保留动态 `require('./ee/ee.module')` 机制，入口增加 license/gating 判定 |
| 验收 | 无 enterprise 模块时应用可正常启动；有模块时入口与接口行为一致 |

### 5. Share / Backup Local API

| 项 | 方案 |
| --- | --- |
| 本地能力 | 微信分享、share shell、static renderer、backup job/restore domain |
| 上游兼容要求 | 新版本并入后不得删字段、改路由语义或移除环境变量 |
| 处理方式 | 以本地服务定义为主，上游只吸收补丁逻辑 |
| 验收 | 分享外链、微信场景、备份作业与下载全部保持可用 |

## 配置与依赖整合

| 类型 | 本地保留 | 上游吸收 | 处理说明 |
| --- | --- | --- | --- |
| 环境变量 | `APP_CHANNEL`、`WECHAT_APP_ID/SECRET`、`BACKUP_LOCAL_PATH` | `EVENT_STORE_DRIVER`、`CLICKHOUSE_URL` 等 | 合并 validation/service，变量可共存 |
| Vite | `allowedHosts`、手动 chunk、proxyTarget | 上游基础修复 | 以本地配置为底，不回退开发可访问性 |
| Docker | 本地 `pg_dump`、loopback 监听、Nginx 模式 | 上游镜像依赖更新中可复用部分 | 不切换到官方 `latest` 镜像 |
| 依赖 | 部分 pnpm/nx 版本与 patch | 上游 `zod4`、Nest 版本、AWS SDK 等 | 在升级分支统一解依赖冲突并重新锁定 |

## 编译与联调门槛

1. `pnpm install --frozen-lockfile` 能通过。
2. `pnpm build` 能通过。
3. client/server 至少各完成一轮 smoke test。
4. 所有 `ee` 代码路径在无企业模块环境下也能启动。
