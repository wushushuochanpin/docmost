## 背景与目标

### 背景问题

1. 上游 `v0.70.1` 已引入一组业务价值明确的新能力，但当前项目仍停留在本地业务分叉版本，长期不升级会持续抬高补丁和安全修复成本。
2. 本地已经完成分享、备份、目录树、RLS、主题、编辑器等深度定制，任何“直接覆盖升级”都会造成业务倒退。
3. 当前最需要的是一条兼容升级路线，而不是一个理论上的版本对齐提案。

### 目标指标

1. P0：把 `v0.70.1` 代码基线并入当前 `main`，保留本地分享、备份、RLS、树导航、主题、编辑器定制能力，零已上线能力回退。
2. P0：完成 `notifications / editor refresh / attachment paste / status node / comments / user deactivation / spaces & groups search` 的代码并入与验收。
3. P0：完成 `page-level permissions / audit logs / MCP / API key restriction / AI menu` 的代码并入与 gating 设计，不因 EE 功能阻断主线升级。
4. P0：升级过程支持 staging 验证和生产回滚，回滚目标时长不超过 `30` 分钟。
5. P1：升级完成后建立月度上游同步节奏，把下一次升级影响面压缩到当前的一半以内。

## 现状审计（As-Is）

1. 本地主线不是纯官方分支，当前产品已承载本地业务需求和对外可见体验。
2. 当前本地主线最不可回退的能力是：folder-first + RLS、分享链路、备份链路、编辑器工具栏/字号、主题和树导航体验。
3. 上游增量中，编辑器、页面权限、设置页、认证和搜索均命中本地已改区域，必须按模块合并。

## 设计理念与决策记录

### 方案对比

| 方案 | 说明 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 直接替换为官方 `v0.70.1` | 以官方代码覆盖本地代码 | 快 | 本地能力高概率丢失，迁移不可控 | reject |
| B. 只 cherry-pick 小补丁 | 只拿补丁不拿功能 | 风险低 | 无法满足“这些功能都需要” | reject |
| C. 以上游 tag 重建新分支再重放本地功能 | 从官方基线回放 47 个本地提交 | 思路清晰 | 重放成本高，冲突更难回溯 | not_preferred |
| D. 以当前 `main` 为基线合并 `v0.70.1` | 从现有业务主线向上吸收官方能力 | 最大化保留本地语义，便于逐块裁剪 | 需要系统化冲突治理 | selected |

### 决策理由

1. 当前 `main` 已经是事实上的业务主线，围绕它升级比“重放所有本地能力”更可控。
2. 大部分本地能力集中在分享、备份、树、编辑器和部署层，直接以本地主线为底座更容易保护这些语义。
3. 上游新能力大多是增量模块，可通过模块级并入矩阵和入口 gating 渐进引入。

## 功能范围与优先级

### P0 必须完成

1. 合并 `v0.70.1` 并保证构建通过。
2. 保留本地分享、备份、RLS、树导航、深色主题、编辑器定制能力。
3. 并入上游通知、编辑器 UI 刷新、attachment paste、status node、comments、user deactivation、spaces/groups search。
4. 并入上游 page permissions、audit logs、MCP、API key restriction、AI menu 的代码路径与开关设计。
5. 完成 staging 迁移演练、主流程回归和回滚预案。

### P1 建议完成

1. 统一 settings 信息架构，清理重复入口。
2. 输出升级后对上游继续同步的基线标签与流程模板。

### P2 暂不纳入

1. 追 `upstream/main` 的未发布提交。
2. 引入 ClickHouse event store 或切换新的部署拓扑。
3. 大规模重构本地分享/备份架构。

## 验收标准

### 功能验收

1. 上游新增的通知、编辑器增强、状态节点、成员管理增强在 staging 可访问并通过基础验收。
2. 本地分享、备份、目录树、主题、字号偏好、Mermaid 预览无行为回退。
3. 设置页新增入口与当前导航不冲突。

### 接口验收

1. page content API、notifications、page permissions、audit、user deactivation 等接口可正常响应。
2. 本地分享与备份接口保持兼容，不出现字段删除或语义反转。

### 回归验收

1. 目录树、分享页、编辑页、登录回跳、备份页、设置页至少各有一组通过用例。
2. 生产回滚演练在预发布环境成功一次。
