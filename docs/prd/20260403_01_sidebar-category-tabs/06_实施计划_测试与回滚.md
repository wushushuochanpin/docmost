## 研发拆解

### Wave 1：数据与接口

1. 新增 `space_sidebar_categories` 表与索引。
2. 为 `page_node_meta` 增加 `sidebar_category_id`。
3. 扩展 `SidebarPageDto` 与 `getSidebarPages` 根查询过滤逻辑。
4. 新增分类 CRUD 与排序接口。
5. 新增节点归类接口。

### Wave 2：客户端视图层

1. 侧边栏顶部新增 Tab 组件。
2. 接入分类列表 query 与根树视图参数。
3. 加入每 Space 记忆上次选中的 Tab。
4. 实现 overflow 规则与空态。

### Wave 3：节点菜单与一致性

1. 根节点菜单新增“设置分类/清除分类”。
2. 当前页不在当前视图时自动回退 `全部`。
3. 删除分类后的前端回退与刷新逻辑。
4. 根节点移动后刷新根树。

### Wave 4：联调与回归

1. 树加载、懒展开与祖先补齐回归。
2. `Pinned` 排序与分类过滤联调。
3. 权限、错误码与文案回归。

## 灰度计划

### 灰度顺序

1. 开发环境：功能正确性与数据结构验证
2. 测试环境：E2E、回归、异常流验证
3. 小范围灰度 Space：观察真实目录规模场景
4. 全量发布

### 观察指标

- `POST /pages/sidebar-pages` P95 耗时
- 分类 CRUD 失败率
- 节点归类失败率
- “当前页回退全部”触发次数
- 前端错误日志中与 `categoryId/viewMode` 相关异常

## 回滚预案

### 轻量回滚

- 隐藏前端 Tab 与分类入口。
- 服务端忽略 `viewMode/categoryId`，恢复单树模式。
- 保留 DB 结构与已写入数据，避免二次损伤。

### 中度回滚

- 若分类 CRUD 本身存在稳定性问题，暂时关闭相关 controller 暴露。
- 已有 `sidebar_category_id` 保留，不再消费。

### 不建议动作

- 不建议在紧急回滚时删除新表或删除字段。
- 不建议清空用户已配置分类数据。
