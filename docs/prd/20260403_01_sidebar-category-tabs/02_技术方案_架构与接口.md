## 架构总览

### 改造层级

- 前端：
  - 侧边树顶部 Tab 视图层
  - 根树查询参数扩展
  - 分类管理与节点归类入口
  - 当前页与当前视图不一致时的自动回退逻辑
- 后端：
  - `sidebar-pages` 根树过滤扩展
  - Space 级分类 CRUD
  - 根节点分类绑定/解绑
- 数据层：
  - 新增 Space 分类配置表
  - 在 `page_node_meta` 增加分类关联字段

### 不变边界

- 不修改 `pages` 主表结构。
- 不修改主内容页路由。
- 不新建第二套树查询接口。
- 不变更现有 `pin/unpin` API 路径与语义。

## 领域边界与服务拆分

| domain_id | domain_goal | frontend_routes | backend_router | backend_service | allowed_commands | out_of_scope |
|---|---|---|---|---|---|---|
| DOMAIN-SIDEBAR-CATEGORY | 维护 Space 级分类配置 | 当前页面容器内侧边栏 | `space.controller` 或分类专用 controller | `SidebarCategoryService` | create/update/delete/reorder/list categories | 页面内容编辑、Pin 管理 |
| DOMAIN-PAGE-NAV-VIEW | 维护根树视图过滤与节点归类 | 当前页面容器内侧边栏 | `page.controller` | `PageService` 或 `PageNavigationService` | filter sidebar roots、assign/clear root category | 分类配置 CRUD、全文检索标签 |

## 前端实现设计

### 组件与状态

- 推荐新增：
  - `SidebarViewTabs`：渲染系统 Tab + 自定义分类 Tab + overflow
  - `SidebarCategoryManageModal`：分类管理弹层
- 推荐扩展：
  - `SpaceTree`：接入当前 `viewMode/categoryId`
  - `page-query.ts`：根树 query key 增加视图参数
  - `page.types.ts` / `tree/types.ts`：节点类型增加 `sidebarCategoryId`

### 查询 Key 设计

- `["sidebar-categories", spaceId]`
- `["root-sidebar-pages", spaceId, viewMode, categoryId ?? null]`
- 子树查询仍沿用 `["sidebar-pages", { pageId, spaceId }]`，不受根视图过滤影响

### 客户端回退规则

1. 页面进入后，读取当前已选 `viewMode/categoryId`。
2. 拉取根树。
3. 若当前页面所属根节点不在结果集中：
   - 清空 `categoryId`
   - 切回 `viewMode=all`
   - 重新拉取根树
4. 再执行当前已有的祖先链路补齐逻辑。

### 视图切换规则

- `全部`
  - 根查询不过滤分类
  - 保持现有置顶优先排序
- `置顶`
  - 仅查询首级 `isPinned=true` 节点
  - 保持 `pinnedAt desc + position asc`
- `分类`
  - 仅查询首级 `sidebarCategoryId = selectedCategoryId` 节点
  - 其下展开继续查询完整子树

## 接口契约

### API-001：扩展 `POST /pages/sidebar-pages`

#### 请求

```json
{
  "spaceId": "uuid",
  "pageId": "uuid|null",
  "cursor": "opaque|null",
  "viewMode": "all|pinned|category",
  "categoryId": "uuid|null"
}
```

#### 请求规则

- `pageId != null` 时：
  - 视为子节点查询
  - 忽略 `viewMode/categoryId`
- `pageId == null` 时：
  - 视为根节点查询
  - `viewMode=all`：返回所有根节点
  - `viewMode=pinned`：返回 `isPinned=true` 的根节点
  - `viewMode=category`：要求 `categoryId` 必填

#### 响应新增字段

- `sidebarCategoryId: string | null`

#### 兼容性

- 当 `viewMode/categoryId` 缺失时，服务端行为与现状完全一致。
- 老客户端忽略 `sidebarCategoryId` 即可。

### API-007：`POST /pages/sidebar-category/assign`

#### 请求

```json
{
  "pageId": "uuid",
  "categoryId": "uuid|null"
}
```

#### 请求规则

- `categoryId = null` 表示清除分类。
- 仅允许首级节点调用。
- 需校验 `page.spaceId == category.spaceId`。

## 错误码建议

| error_code | 场景 | 文案建议 |
|---|---|---|
| `SIDEBAR_CATEGORY_NOT_FOUND` | 分类不存在 | 分类不存在或已被删除 |
| `SIDEBAR_CATEGORY_NAME_DUPLICATED` | 分类重名 | 当前 Space 下已存在同名分类 |
| `SIDEBAR_CATEGORY_LIMIT_EXCEEDED` | 分类数量超限 | 分类数量已达上限，请先清理 |
| `ROOT_NODE_ONLY_CATEGORY_ASSIGNMENT` | 非首级节点设分类 | 仅首级文件或文件夹可设置分类 |
| `CATEGORY_SPACE_MISMATCH` | 分类与页面不在同一 Space | 请选择当前 Space 下的分类 |

## 查询与排序实现建议

### 根查询 SQL 过滤规则

- 统一入口仍为 `getSidebarPages`。
- `pageId is null` 时追加：
  - `viewMode=all`：无额外 where
  - `viewMode=pinned`：`pageNodeMeta.isPinned = true`
  - `viewMode=category`：`pageNodeMeta.sidebarCategoryId = :categoryId`
- `pageId is not null` 时不加视图过滤。

### 排序规则

- `全部` / `分类`：
  - `isPinned desc`
  - `pinnedAt desc`
  - `pages.position asc`
- `置顶`：
  - `pinnedAt desc`
  - `pages.position asc`

## 一致性与实时性

- Phase 1 不强制做 websocket 增量同步。
- 节点归类、分类 CRUD 完成后，统一失效以下查询：
  - `sidebar-categories`
  - `root-sidebar-pages`
- 子树 query 不必全量失效，除非根节点身份发生变化。

## 兼容性策略

1. 不传新参数时行为与旧版一致。
2. 分类不存在时，前端自动回退到 `全部`。
3. 节点 `sidebarCategoryId` 缺失时按“未分类”处理。
4. 删除分类后，如果当前选中的就是被删分类，前端立即回退 `全部`。
