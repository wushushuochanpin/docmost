## 背景

1. 当前 Space 侧边栏只有一棵根树，根节点过多时，用户只能依赖滚动、置顶和搜索来定位内容，浏览成本高。
2. 现有 `Pinned` 仅解决优先级排序，不解决“按主题收敛首级目录”的导航问题。
3. 需求里的 `全部 / 置顶 / 创业` 本质上是三类不同导航视图，若直接做成“所有节点通用多标签”，会引入树结构断裂、重复出现和排序冲突。

## 关键决策

1. 树结构继续代表“真实父子关系”，Tab 代表“首级浏览视图”，两者不混用。
2. 分类只作用于首级文件/文件夹，且为单分类；子节点跟随所属首级节点展示，不单独参与 Tab 分类。
3. `全部`、`置顶` 为系统视图；`创业` 等为自定义分类视图。系统视图不落表，自定义分类落表。
4. `Pinned` 维度保留独立语义；在 Tab 维度仅筛选首级置顶项，不把本期扩展成全局快捷入口系统。
5. 复用现有 `page_node_meta` 元数据层，新增 `sidebar_category_id`，不把分类字段塞入 `pages` 主表，也不做 many-to-many 标签系统。
6. 复用现有 `POST /pages/sidebar-pages` 作为根树查询入口，仅在根查询场景下增加视图过滤参数。
7. 当当前页面不属于已选 Tab 视图时，客户端自动切回 `全部`，优先保证“当前页与侧边树一致可见”。

## 非目标

1. 本期不做“全文档通用标签系统”。
2. 本期不支持一个节点属于多个分类。
3. 本期不支持子级节点直接打分类。
4. 本期不做跨 Space 共享分类。
5. 本期不做分类与搜索联动的高级 Facet 检索。
