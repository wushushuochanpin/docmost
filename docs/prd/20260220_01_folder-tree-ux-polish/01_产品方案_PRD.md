## 背景与目标

### 背景问题

- 置顶节点缺少显式视觉标识，用户需要通过位置猜测状态。
- 文件名与操作入口视觉基线不统一，降低列表可扫描性。
- 目录统计粒度过粗，缺少“文件夹/文件”维度。
- 侧边树需从设计稿引入：点击展开/折叠、底色动态效果、数量展示；且设计稿中若未显示「三点」「加号」时，实现中必须保留该两个入口。

### 目标指标

- G1：置顶节点识别耗时（可用性走查）下降，首次识别成功率达到 100%。
- G2：侧边树关键节点（名称、操作入口、状态徽标）水平视觉对齐一致。
- G3：目录页展示“文件夹数 + 文件数”，减少用户二次判断成本。
- G4：文档编辑时，编排/格式化工具栏在内容区顶部吸顶，滚动页面时始终可见，减少反复定位工具栏的成本。

## 现状审计（As-Is）

- 现有页面/交互盘点：
  - `SpaceTree`：节点操作区通过 hover 展示，但基线对齐不稳定。
  - `FolderView`：顶部仅展示 `items` 总数。
  - 页面编辑器：格式化工具栏当前为选中文本后出现的 BubbleMenu，无吸顶常驻栏。
- 现有接口盘点：
  - 复用 `POST /pages/sidebar-pages` 获取子节点列表（含 `nodeType/isPinned`）。
- 现有数据表盘点：
  - 已存在 `page_node_meta.is_pinned/node_type`，本期不新增字段。
- 现有权限与埋点盘点：
  - 继续沿用 Space 读写权限，不新增权限点。

### 灰度策略

- Stage 1：测试 workspace 全量验证。
- Stage 2：小范围生产 workspace 开启（10%-30%）。
- Stage 3：全量上线。

### 回滚策略

- 触发条件：节点点击异常、样式错位、目录统计错误。
- 回滚动作：回退前端组件改动（`SpaceTree` + `FolderView`）并重新发布。
- 目标时长：30 分钟内恢复。

## 验收标准

- ACC-001：置顶节点展示独立标识，且可区分 file/folder 类型。
- ACC-002：节点名称与操作入口在默认、hover、selected 状态均保持水平视觉居中；侧边树具备点击展开/折叠、底色动态效果及数量展示（以设计稿为准）；三点（更多菜单）与加号（新建）入口必须保留。
- ACC-003：目录页顶部显示“X folders · Y files”，数值与当前目录子项一致。
- ACC-004：原有排序规则（置顶优先 + position）不被破坏。
- ACC-005：未新增接口、未新增数据库迁移。
- ACC-006：编辑文档时，编排/格式化工具栏在内容区顶部吸顶展示，滚动页面时工具栏保持可见；现有加粗、斜体、标题、列表、对齐、链接、图片、表格等能力均保留。
