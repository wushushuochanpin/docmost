## 背景与目标

### 背景问题

- 置顶节点缺少显式视觉标识，用户需要通过位置猜测状态。
- 文件名与操作入口视觉基线不统一，降低列表可扫描性。
- 目录统计粒度过粗，缺少“文件夹/文件”维度。
- 侧边树需从设计稿引入：点击联动展开并进入页面、底色动态效果、数量展示；设计稿已更新并包含三点与加号；左侧树区域自定义宽度（拖拽调整侧边栏宽度）必须保留。
- 页面头部信息层级不稳定：左上角面包屑与正文大标题并存，但滚动后缺少稳定的当前文档标题锚点；面包屑点击语义不清晰时价值降低。
- 吸顶工具栏当前视觉更接近浮层/弹窗，不符合“嵌入灰色吸顶条”的认知模型；且标题与工具栏未形成稳定的联合吸顶区。

### 目标指标

- G1：置顶节点识别耗时（可用性走查）下降，首次识别成功率达到 100%。
- G2：侧边树关键节点（名称、操作入口、状态徽标）水平视觉对齐一致。
- G3：目录页展示“文件夹数 + 文件数”，减少用户二次判断成本。
- G4：文档编辑时，编排/格式化工具栏在内容区顶部吸顶，滚动页面时始终可见，减少反复定位工具栏的成本。
- G5：侧边树节点统计准确率（一级直接下级总数、全部下级总数）达到 100%（抽样与 SQL 校验一致）。
- G6：页面滚动时，工具栏与标题组成稳定吸顶区（工具栏在上、缩小标题在下），始终可识别当前文档。

## 现状审计（As-Is）

- 现有页面/交互盘点：
  - `SpaceTree`：节点操作区通过 hover 展示，但基线对齐不稳定；行点击进入页面，展开/收起主要依赖箭头区域。
  - `FolderView`：顶部仅展示 `items` 总数。
  - 页面编辑器：格式化工具栏当前为选中文本后出现的 BubbleMenu，无吸顶常驻栏。
- 现有接口盘点：
  - 复用 `POST /pages/sidebar-pages` 获取子节点列表（含 `nodeType/isPinned`），尚未返回节点聚合统计字段。
- 现有数据表盘点：
  - 已存在 `page_node_meta.is_pinned/node_type`，本期不新增字段。
- 现有权限与埋点盘点：
  - 继续沿用 Space 读写权限，不新增权限点。

### 灰度策略

- Stage 1：测试 workspace 全量验证（含深层目录统计）。
- Stage 2：小范围生产 workspace 开启（10%-30%）。
- Stage 3：全量上线。

### 回滚策略

- 触发条件：节点点击异常、样式错位、统计错误或 API 延迟显著上升。
- 回滚动作：先回退前端组件改动（`SpaceTree` + `FolderView` + 编辑器）；若统计异常持续，再回退 `API-001` 聚合字段逻辑。
- 目标时长：30 分钟内恢复。

## 验收标准

- ACC-001：置顶节点展示独立标识，且可区分 file/folder 类型。
- ACC-002：节点名称与操作入口在默认、hover、selected 状态均保持水平视觉居中；点击节点时 folder 节点可展开并进入页面（同一次操作）；箭头点击仅展开/收起不跳转；三点与加号按设计稿保留；左侧树区域自定义宽度（拖拽调整侧边栏）保留。
- ACC-003：每个节点展示“一级下级总数 + 全部下级总数”，计数口径如下：`directChildCount=仅 depth=1 且 nodeType in (folder,file)`，`descendantTotalCount=全部 depth>=1 的 folder+file`；目录页顶部继续显示“X folders · Y files”。兼容字段 `directChildFolderCount` 保留（语义为一级目录数）。
- ACC-004：原有排序规则（置顶优先 + position）不被破坏。
- ACC-005：不新增接口路径、不新增数据库迁移；允许 `POST /pages/sidebar-pages` 响应新增兼容字段。
- ACC-006：编辑文档时，编排/格式化工具栏在内容区顶部吸顶展示，位于标题上方且与标题构成同一固定区域；现有加粗、斜体、标题、列表、对齐、链接、图片、表格等能力均保留；BubbleMenu 保留为选区快捷增强。
- ACC-007：标题在吸顶区采用缩小字号展示，并与工具栏共同固定；工具栏视觉融入灰色吸顶条，不再使用独立白底圆角容器。
- ACC-008：面包屑语义为“祖先导航 + 当前定位”：祖先节点可点击导航，当前节点仅文本展示不可点击；当不存在祖先节点时隐藏面包屑区域。
