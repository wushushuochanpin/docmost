本文档用于定义实施阶段、测试矩阵与回滚方案。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

## 实施计划

1. 开发阶段：
   - 前端：完成 `SpaceTree`/`FolderView` 样式与交互改造、节点统计展示、页面编辑器吸顶工具栏。
   - 后端：在 `POST /pages/sidebar-pages` 同一路径扩展统计字段返回（不新增接口路径）。
2. 自测阶段：执行 TS 编译、关键交互走查、统计口径对账。
3. 联调阶段：在测试 workspace 验证目录数据、置顶状态、节点统计准确性、点击联动行为及编辑器吸顶工具栏。
4. 发布阶段：按 workspace 小流量灰度发布。

## 发布与灰度

- 发布方式：前后端常规发布（接口路径不变）。
- 灰度策略：测试 workspace -> 10% 生产 workspace -> 30% -> 全量。
- 灰度观察指标：
  - 页面渲染报错率。
  - 树节点点击、重命名与导航成功率。
  - 节点统计显示正确率（抽样 SQL 对账）。
  - `POST /pages/sidebar-pages` 延迟（P95/P99）与错误率。
  - 编辑器吸顶工具栏展示与编排操作成功率。

## 回滚方案

- 触发条件：
  - 关键交互失效（无法点击节点/无法操作菜单、编排按钮失效、侧边栏无法拖拽调宽）。
  - 样式严重错位影响可用性。
  - 节点统计与实际数据明显不一致，或 API-001 延迟异常上升。
- 回滚步骤：
  1. 回退前端提交（`SpaceTree`、`FolderView`、`global-app-shell` 及编辑器相关改动文件）。
  2. 如统计或性能问题仍存在，回退后端 `getSidebarPages` 聚合字段扩展提交。
  3. 重新构建并发布，验证核心页面恢复。
- 回滚目标时长：30 分钟内。
