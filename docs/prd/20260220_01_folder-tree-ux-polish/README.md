## 背景

1. 置顶节点当前仅通过排序体现，缺少独立标识，用户难以快速区分置顶与非置顶。
2. 侧边树中“文件名 + 操作入口（更多/新建）”视觉不在同一水平中心线，影响可读性与观感。
3. 目录结构统计信息不足，用户难以快速判断目录规模。

## 关键决策

1. 不新增接口路径，复用 `POST /pages/sidebar-pages`，仅扩展响应兼容字段以支持节点统计。
2. 侧边树 folder 行点击执行“展开并进入页面”联动；箭头点击仅展开/收起。
3. 每个节点展示“双口径统计”：`directChildFolderCount`（一级目录数）+ `descendantTotalCount`（全部下级总数）。
4. 置顶标识采用“pin + 节点类型”组合徽标，避免仅靠排序造成语义不清。
5. 本次按 UI/交互改造处理，不触发数据库 schema 与迁移变更。
6. 本次 UI 以 Figma 设计稿（UI Design Improvement Proposal）为视觉与交互参考；所有改动均不删减现有功能，回归以 06 测试矩阵与 07 检查清单为准。
