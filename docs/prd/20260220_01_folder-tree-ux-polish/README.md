## 背景

1. 置顶节点当前仅通过排序体现，缺少独立标识，用户难以快速区分置顶与非置顶。
2. 侧边树中“文件名 + 操作入口（更多/新建）”视觉不在同一水平中心线，影响可读性与观感。
3. 目录页仅展示总 item 数，无法直观看到“文件夹数 vs 文件数”。

## 关键决策

1. 不新增后端接口，复用 `POST /pages/sidebar-pages` 返回数据并在前端完成计数与展示。
2. 置顶标识采用“pin + 节点类型”组合徽标，避免仅靠排序造成语义不清。
3. 本次按 UI/交互改造处理，不触发数据库 schema 与迁移变更。
4. 本次 UI 以 Figma 设计稿（UI Design Improvement Proposal）为视觉与交互参考；所有改动均不删减现有功能，回归以 06 测试矩阵与 07 检查清单为准；涉及“影响当前功能”或“当前无此功能”的条目须经产品确认后再实施。

## 非目标

1. 本期不调整置顶排序规则。
2. 本期不新增“子孙节点总量”统计，仅展示当前目录直接子项的 folder/file 数量。
3. 本期不改动权限模型。
