# 03 数据模型与存储设计

**成文日期**：2026-03-08 23:07:46 UTC+8
**最后修订**：2026-03-08 23:07:46 UTC+8

本文档用于定义核心实体、字段与存储策略。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## 设计原则

1. 自研能力使用独立命名空间，避免和企业版实现混淆。
2. 尽量复用现有 `users`、`workspaces`、`spaces` 作为外键，不复制核心主数据。
3. 新表命名统一采用 `sc_` 前缀，表示 SuperChat 自研替代域。
4. 默认不依赖当前升级引入的 `audit`、`page_access`、`page_permissions` 表，除非法务与架构双确认。

## 表设计

### 1. `sc_api_tokens`

用途：存储个人与工作区级 API Token 元信息。

核心字段：

- `id`
- `workspace_id`
- `owner_user_id`
- `creator_user_id`
- `name`
- `token_prefix`
- `token_hash`
- `scope_json`
- `is_workspace_managed`
- `status`
- `expires_at`
- `last_used_at`
- `last_used_ip`
- `created_at`
- `updated_at`
- `revoked_at`

约束：

- `token_hash` 唯一
- `workspace_id + owner_user_id + name` 建普通索引
- 工作区级 Token 与个人 Token 通过 `is_workspace_managed` 区分

### 2. `sc_api_token_events`

用途：追踪 Token 创建、轮换、撤销、调用异常。

字段：

- `id`
- `workspace_id`
- `api_token_id`
- `event_type`
- `actor_user_id`
- `metadata_json`
- `created_at`

### 3. `sc_security_policies`

用途：存储工作区安全策略。

字段：

- `workspace_id`（主键）
- `disable_public_sharing`
- `restrict_token_creation_to_admins`
- `enforce_mfa`
- `allowed_email_domains_json`
- `default_token_ttl_days`
- `updated_by`
- `updated_at`

### 4. `sc_auth_providers`

用途：存储自研身份提供商配置。

字段：

- `id`
- `workspace_id`
- `provider_type`
- `name`
- `status`
- `client_id`
- `client_secret_encrypted`
- `issuer_url`
- `metadata_url`
- `saml_entrypoint`
- `saml_certificate`
- `ldap_url`
- `ldap_bind_dn`
- `ldap_bind_secret_encrypted`
- `config_json`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

### 5. `sc_audit_events`

用途：记录自研替代域的审计事件。

字段：

- `id`
- `workspace_id`
- `actor_user_id`
- `actor_type`
- `event`
- `resource_type`
- `resource_id`
- `space_id`
- `changes_json`
- `metadata_json`
- `ip_address`
- `user_agent`
- `created_at`

索引：

- `(workspace_id, id desc)`
- `(workspace_id, event, id desc)`
- `(workspace_id, actor_user_id, id desc)`

### 6. `sc_audit_retention`

用途：配置审计保留策略。

字段：

- `workspace_id`（主键）
- `retention_days`
- `updated_by`
- `updated_at`

## 新增表 vs 改造表决策

| 对象 | 处理方式 | 原因 |
| --- | --- | --- |
| `users` | 复用 | 核心主数据，已稳定 |
| `workspaces` | 复用少量字段读取 | 仅作为上下文，不扩企业专属语义 |
| `audit` | 不依赖 v1 | 避免和企业实现混用 |
| `page_access` | 不在本专题内使用 | 本期不做页面级权限 |
| `auth_providers` | 不直接复用 | 避免和企业 SSO 语义耦合 |
| `sc_*` 新表 | 新建 | 合规、自主、可迁移 |

## 迁移步骤

### 首期迁移

1. 新建 `sc_api_tokens`
2. 新建 `sc_api_token_events`
3. 新建 `sc_security_policies`
4. 新建 `sc_auth_providers`
5. 新建 `sc_audit_events`
6. 新建 `sc_audit_retention`

### 回滚策略

1. 路由与 capability 关闭
2. 停止向 `sc_audit_events` 继续写入
3. Token 相关服务停写，保留只读查询
4. 仅当确认无依赖后，执行降级迁移

## 数据兼容与保留

1. 自研域默认不读取企业版 `audit` 表。
2. 若未来购买企业授权，可设计离线迁移脚本把 `sc_*` 数据映射到授权方案。
3. 审计日志默认保留 365 天，可配置。
4. Token 明文永不入库，只保存 hash 与前缀。

## 权限与数据隔离

| 表 | 读权限 | 写权限 |
| --- | --- | --- |
| `sc_api_tokens` | 本人 / Admin | 本人创建受策略控制，Admin 可代管 |
| `sc_security_policies` | Admin/Owner | Admin 或 Owner |
| `sc_auth_providers` | Admin/Owner | Admin 或 Owner |
| `sc_audit_events` | Owner 默认，安全只读可扩展 | 系统服务写入 |
| `sc_audit_retention` | Owner | Owner |

## 代码生成与类型

1. 新表加入 Kysely migration 后重新生成类型定义。
2. 不复用企业版类型目录。
3. 所有 DTO 与 Repo 归属自研模块，不放入 `ee` 命名空间。
