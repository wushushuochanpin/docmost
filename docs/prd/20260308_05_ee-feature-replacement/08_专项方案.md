## 专项一：代码来源分级矩阵

| 来源 | 示例 | 允许动作 | 备注 |
| --- | --- | --- | --- |
| Green | 非 `ee` 的设置布局、通用表单、角色判断、三方协议库 | 复用或改造 | 需保留 AGPL 与三方许可证说明 |
| Yellow | 企业功能的页面行为、字段集合、交互流程 | 借鉴与重写 | 不得复制实现文本 |

## 专项三：推荐交付顺序

### Wave 1：Token 基础设施

- 个人 Token
- 工作区 Token 管理
- 限制仅管理员创建
- Token 审计事件
- Audit Log
- 设置页源码入口
- `/api/version.sourceUrl`

### Wave 2：Security & SSO

- 禁用公开分享
- 强制 MFA
- OIDC

### Future：更复杂企业能力

- SAML / LDAP
- 页面级权限
- 评论企业增强
- 更细粒度搜索与导入

## 专项五：验收要求

1. 每个模块必须在设计文档中写出可参考的公开来源和禁止引用的源码范围。
2. 每个 PR 必须包含：
   - 来源说明
   - 权限测试
   - 审计测试
3. 安全模块上线前必须完成：
   - 兜底本地登录验证
   - 回滚演练
   - 错误注入测试

## 专项六：AGPL 履约交付物

1. 每个部署版本必须有对应的源码归档与提交号映射。
2. 产品内必须存在可访问的源码获取入口。
3. 当前已确认入口为：
   - 设置页底部入口
   - `/api/version.sourceUrl`
4. 发布说明必须包含：
   - 当前版本号
   - 对应 commit sha
   - 源码归档链接
   - 第三方许可证清单位置
5. 若上线版本与源码归档不一致，发布不通过。
