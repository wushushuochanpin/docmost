## 实施阶段

说明：`Wave 1` 发布范围由“阶段 1：API Token”和“阶段 2：Audit Log”组成，二者同属首个正式交付波次。

### 阶段 0：法务与架构决策

- 固化已确认的 AGPL 履约方案
- 明确源码归档目录、版本映射表与产品内获取入口
- 输出来源分级清单
- 建立能力开关

### 阶段 1：API Token

- 个人 Token CRUD
- 工作区 Token 管理
- Token Scope 与管理员限制开关
- Token 审计事件
- 设置页源码入口
- `/api/version` 或等价接口补充源码定位字段

### 阶段 2：Audit Log

- 审计写表
- 审计列表页
- 筛选与分页
- 保留期设置

### 阶段 3：Security 基础能力

- 公共分享禁用
- 域名白名单
- 强制 MFA
- 安全策略审计

### 阶段 4：OIDC SSO

- Provider CRUD
- 测试连接
- 登录回调
- 灰度启用

### 阶段 5：SAML / LDAP

- 按需求优先级排期
- 与 OIDC 拆分发布

## 发布策略

- 发布方式：测试环境先行，随后工作区级灰度，最后正式全量
- 灰度维度：
  - 环境：`book-test` -> `book`
  - 工作区：白名单
  - 角色：Owner/Admin 先开
- 灰度观察期：
  - Token：3 天
  - 审计：7 天
  - OIDC：7 到 14 天

## 测试矩阵

### 功能测试

- 用户 Token 创建、查看、撤销
- 管理员 Token 管理
- 审计日志筛选、分页、保留期

### 回归测试

- 账号登录
- 页面编辑
- 分享页
- 空间与成员管理

### 性能测试

- 审计日志分页查询
- 批量 Token 列表查询

## 验收门槛

1. 测试环境发布通过
2. 全部核心接口有自动化用例
3. 审计与 Token 写入链路有人工验收
4. 安全评审与来源核查通过
5. 发布、灰度、回滚文档齐备
6. 当前运行版本可通过产品入口拿到对应源码位置

## 回滚方案

### 触发条件

- 登录成功率显著下降
- Token 权限失控或错误放权
- 审计日志持续写入失败
- 大面积 5xx 或高优先级安全缺陷

### 回滚步骤

1. 关闭 capability 开关
2. 设置页菜单恢复灰态或隐藏
3. 停止新 Token 创建
4. 停止新的 Provider 认证入口
5. 审计写入切换为只读保留
6. 保留源码获取入口，但将说明同步切回上一稳定版本

### 回滚时长

- 配置级回滚：5 分钟内
- 应用级回滚：30 分钟内
- 数据级回滚：仅在确认无引用后离线执行

## 环境与联调顺序

1. 本地开发验证
2. `book-test` 测试环境发布
3. 测试工作区联调
4. 小流量正式工作区灰度
5. 正式全量发布

## 运维检查项

- 端口仍只暴露 `127.0.0.1`
- Nginx 路由未误指向旧实例
- 数据库新增索引已创建
- 清理任务未误删审计数据
- Token 哈希与加密密钥已正确配置
- 源码获取入口可访问且版本号与当前部署一致
