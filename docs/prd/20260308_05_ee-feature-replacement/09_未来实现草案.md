# 09 未来实现草案

**成文日期**：2026-03-08 23:07:46 UTC+8
**最后修订**：2026-03-08 23:07:46 UTC+8

本文档用于记录后续阶段规划与边界。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## 未来阶段规划

### Future Stage A：页面级权限

- 目标：替代企业版的页面级权限与发布控制
- 风险：与当前分享模型、空间树、缓存和迁移冲突高
- 前置条件：
  - Token / Audit / Security 稳定
  - 法务确认此能力实现边界

### Future Stage B：更完整的企业搜索与导入

- 目标：增强附件检索、Confluence / DOCX 导入
- 风险：第三方解析器、版权与存储成本高
- 建议：放入独立专题，不和本包合并开发

### Future Stage C：MCP 深度支持

- 目标：为 AI Assistant 提供更稳定的工作区接入
- 依赖：
  - Token Scope
  - 审计追踪
  - 访问限流

## 演进边界

1. 当前专题不承诺“完全对齐企业版所有细节”。
2. 当前专题优先实现“合规可上线”版本，而不是一比一复刻。
3. 若未来采购商业授权，应重新评估是否继续维护自研替代模块。

## 风险记录

1. 若未来上游把同类能力开源，当前自研实现可能需要收敛或废弃。
2. 若未来法务认定当前仓集成方式仍存在 AGPL 派生争议，则需进一步拆分部署边界。
3. 若未来业务要求快速支持更多企业能力，阶段节奏可能被压缩，需重新评审。

## 收敛建议

1. 每完成一个阶段，都重新评估“继续自研”还是“切换商业授权”。
2. 任何未来阶段都必须先复用本包的来源分级与审计模板。
3. 若阶段收益低于维护成本，及时终止，不追求全量复刻。
