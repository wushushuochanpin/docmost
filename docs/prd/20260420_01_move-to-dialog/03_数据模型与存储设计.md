本期不修改任何服务端数据库表结构。移动操作通过已有字段完成：

```
pages 表
├── id: string (PK)
├── parentPageId: string | null   ← 移动时更新此字段
├── position: string | null       ← 移动时置 null，后端追加到末尾
├── spaceId: string               ← 跨 Space 移动时更新此字段
└── nodeType: "file" | "folder"   ← 用于校验目标层级规则
```

## 客户端存储设计（新增）

### localStorage 结构

**Key**：`docmost:recent-pages:{workspaceId}`；无法取得 workspaceId 时降级为 `docmost:recent-pages:global`。

**Value**（JSON string）：

```typescript
type RecentPagesStore = RecentPageEntry[];

interface RecentPageEntry {
  pageId: string;       // pages.id，用于后代过滤
  slugId: string;       // 用于构造 URL
  title: string;        // 展示用，允许过期（不实时更新）
  icon: string | null;  // emoji 或 null
  nodeType: "file" | "folder";
  spaceId: string;      // 用于跨 Space 检测
  spaceName: string;    // Space 展示名
  spaceSlug: string;    // 用于构造跨 Space URL
  visitedAt: number;    // Date.now() 时间戳，用于排序
  workspaceId?: string; // workspace 维度隔离
}
```

**存储规则**：

| 规则 | 描述 |
|---|---|
| 容量上限 | 最多 10 条，FIFO（超出时删除最旧条目） |
| 去重 | 同一 `pageId` 已存在时，更新 `visitedAt` 并移到数组首位 |
| 过期 | 无 TTL（浏览器 localStorage 无自动过期），数据可能因页面删除而过期 |
| 过期处理 | Modal 打开时展示时不额外验证存活性，点击后若 API 返回 404 则提示并从列表移除 |
| 清空 | 用户退出登录时清空 `docmost:recent-pages:` 前缀下所有 key（在 logout 流程中处理） |

**读取时过滤规则**：

1. 过滤掉 `pageId === currentMovingPageId`（不能移到自己）
2. 过滤掉 `pageId` 在当前移动页面的后代 ID 列表中的条目（不能移到子孙）
3. 按 `visitedAt` 降序排列，取前 6 条展示
4. 后代 ID 列表来源：前端基于已加载的侧边树缓存推算；未加载后代由 `POST /pages/move` 后端 cycle guard 兜底

## 数据流向图

```
用户访问页面
  └── page.tsx useEffect
        └── recordRecentPage()
              └── localStorage["docmost:recent-pages"] (写)

用户打开 MoveToModal
  └── use-recent-pages.getRecentPages()
        └── localStorage["docmost:recent-pages"] (读)
              └── 过滤 + 排序 → RecentPageEntry[]

用户搜索
  └── POST /search/suggest → IPage[]
        └── 转换为 MoveTargetPage[]

用户粘贴 URL
  └── 正则提取 slugId
        └── POST /pages/info { pageId: slugId, includeContent: false } → IPage
              └── 转换为 MoveTargetPage

用户确认移动（同 Space）
  └── POST /pages/move { pageId, parentPageId, position: null }
        └── 服务端计算目标子树末尾 position
              └── 更新 pages.parentPageId, pages.position
              └── 失效 queryClient 缓存 → 树刷新

用户确认移动（跨 Space）
  └── POST /pages/move-to-space { pageId, spaceId }
        └── 更新 pages.spaceId（服务端）
  └── POST /pages/move { pageId, parentPageId, position: null }
        └── 更新 pages.parentPageId（服务端）
              └── 清空 queryClient 缓存 → 树刷新 + 路由跳转
```

## 数据一致性与过期处理

| 场景 | 问题 | 处理方式 |
|---|---|---|
| 最近访问的页面已被删除 | localStorage 中有记录但页面不存在 | Modal 展示时不过滤，点击后 API 返回 404 时从列表中移除并提示 |
| 最近访问的页面 title 已更新 | localStorage 存储的 title 是快照 | 接受过期，不影响移动操作正确性；P1 阶段可在打开时批量刷新 |
| 搜索结果中的页面已被删除 | `search/suggest` 返回已删除页面（软删除边界） | 后端 `search/suggest` 已过滤 `deletedAt != null` 的页面 |
| 跨 Space 移动第一步成功、第二步失败 | 页面已在目标 Space 但未在目标父级 | 提示错误；用户可再次打开 MoveToModal 执行第二步（页面已在目标 Space，按同 Space 移动处理） |
| 移动到自身或后代 | 前端只知道已加载树节点，存在漏判 | 后端最终阻断并返回 400；前端保留目标选择并提示 |
