# 07 研发实施清单：前后端任务拆解

**成文日期**：2026-03-06 15:56:17 UTC+8
**最后修订**：2026-03-08 10:28:40 UTC+8

本文档用于把 PRD 转成可执行研发清单。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## 文档目的

本清单回答四个问题：

1. 先做什么，后做什么
2. 具体改哪些文件
3. 每一步的完成定义是什么
4. 哪些事项不应过早投入

## 总体实施原则

1. 先处理正文首屏，再处理辅助能力。
2. 先减前端运行时负担，再替换正文渲染形态。
3. 先保留兼容路径，再做默认切换。
4. 每个阶段都必须可独立验证、可独立回滚。

## 里程碑拆解

| 里程碑 | 目标 | 建议负责人 | 进入条件 | 完成定义 |
| --- | --- | --- | --- | --- |
| M1 | 正文优先改造 | 前端 | PRD 冻结 | 分享页 1s 内出现 skeleton 或正文 |
| M2 | 只读阅读器减重 | 前端 | M1 完成 | 首屏 JS gzip 明显下降，重内容不阻塞正文 |
| M3 | 分享页独立化 | 前端 + 发布/运维 | M2 完成 | `/share/*` 可独立切换新旧实现 |
| M4 | 静态 HTML 阅读器替代 TipTap | 前端 + 后端 | M3 完成 | 正常分享正文路径默认不挂 TipTap 只读运行时 |
| M5 | 长文档首包与分段加载 | 后端 + 前端 | M4 完成且长文档仍慢 | 首包冗余消失，超长文档可分段续传 |
| M6 | 可选补偿项 | 后端 + 前端 | M5 后指标仍不达标 | 服务端渲染耗时、基础包体进一步下降且兼容回退 |

## M1：正文优先改造

### 目标

- 消除白屏
- 让正文先于壳层出现
- 清理 happy path 不必要请求

### 任务清单

| task_id | 任务 | 目标文件 | 动作 | 完成定义 |
| --- | --- | --- | --- | --- |
| FE-M1-001 | 分享页增加 skeleton | `apps/client/src/pages/share/shared-page.tsx` | `isLoading` / `!data` 时渲染轻量 skeleton，不再返回空节点 | 移动端首屏非空白 |
| FE-M1-002 | redirect 页补 loading 态 | `apps/client/src/pages/share/share-redirect.tsx` | redirect 等待阶段渲染 skeleton 或最小 loading 卡片 | `/share/:shareId` 不再白屏 |
| FE-M1-003 | 清理 happy path 无关请求 | `apps/client/src/pages/share/shared-page.tsx` | 将 `useCurrentUser()` 与仅错误态使用的 share meta 请求延后或条件触发 | 正文路径首屏请求减少 |
| FE-M1-004 | 首屏请求分层 | `apps/client/src/features/share/queries/share-query.ts` | 明确哪些 query 属于正文首屏必需、哪些属于延后请求 | query 责任边界清晰 |
| FE-M1-005 | 录制基线与对比数据 | 构建脚本 / 文档附录 | 记录优化前后首屏录屏、build 统计、关键请求数 | 有对比证据，非主观判断 |

### M1 验证项

1. 公开分享页 1 秒内出现 skeleton 或正文。
2. 受限分享页在密码门禁前不白屏。
3. 正文路径不再强依赖 `currentUser`。
4. 不因 skeleton 影响 SEO / title / noindex 逻辑。

### 目标

- 从根因上剥离分享阅读场景与编辑态重扩展
- 允许重内容先占位、后加载

### 任务清单

| task_id | 任务 | 目标文件 | 动作 | 完成定义 |
| --- | --- | --- | --- | --- |
| FE-M2-001 | 新建只读扩展清单 | `apps/client/src/features/editor/extensions/readonly-extensions.ts` | 定义阅读场景最小扩展集 | 不再依赖 `mainExtensions` |
| FE-M2-002 | 改造只读编辑器接线 | `apps/client/src/features/editor/readonly-page-editor.tsx` | 从 `mainExtensions` 切换到 `readonlyExtensions` | 分享只读路径不加载编辑态全量扩展 |
| FE-M2-003 | 定义重内容降级策略 | Drawio / Excalidraw / Embed 相关 view 文件 | 先展示占位卡片，再按需 lazy import 真正渲染器 | 正文先出现，重块随后补齐 |
| FE-M2-004 | Mention 降级 | Mention 相关 view / 只读扩展 | 只保留阅读所需跳转语义，不加载 suggestion 体系 | 分享页不再带入编辑建议能力 |
| FE-M2-005 | 产物体积复测 | `pnpm --filter client build` 与统计脚本 | 记录分享路由递归依赖闭包体积变化 | 满足 G3 或接近目标 |

### M2 验证项

1. 含表格、代码块、图片、链接、Callout 的普通正文展示无回归。
2. Drawio / Excalidraw / Embed 页面先看到正文，再看到占位，再加载完整内容。
3. 包体下降有统计证据，而不是仅凭体感。

## M4：静态 HTML 阅读器替代 TipTap

### 目标

- 正常分享正文路径不再默认挂载 TipTap 只读编辑器
- 服务端直接输出 share-safe HTML
- 客户端仅对少数交互块做按需挂载
- 分享页遵守 Reader Contract：固定 Reader 主题、代码块纯展示、`Mermaid` 一期源码降级

### 任务清单

| task_id | 任务 | 目标文件 | 动作 | 完成定义 |
| --- | --- | --- | --- | --- |
| BE-M4-001 | 新建分享安全 renderer 服务 | `apps/server/src/core/share/` 下新 service 文件 | 基于 `jsonToHtml / generateHTML` 封装 share-safe HTML 输出 | 后端可独立生成 `rendered.html` |
| BE-M4-002 | 定义 rendered payload 契约 | `apps/server/src/core/share/dto/share.dto.ts`、`share.controller.ts` | 扩展 `POST /shares/page-info` 响应结构，新增 `rendered` 字段 | 契约清晰且兼容 legacy 字段 |
| BE-M4-003 | 增加 HTML 清洗与 URL 重写 | renderer service / helper | 去除危险标签、事件属性、危险协议，重写资源 URL | 满足 ACC-015 |
| BE-M4-004 | 增加 renderer cache 钩子 | renderer service / cache helper | 先支持内存或 Redis cache key 设计，不强制持久化 | 可按 contentHash 命中 |
| FE-M4-005 | 新建静态正文容器 | `apps/client/src/features/share/components/shared-page-html-content.tsx`（建议新建） | 用受控容器渲染 `rendered.html`，替代 happy path 的 `ReadonlyPageEditor` | 正常正文直接渲染 HTML |
| FE-M4-006 | 构建 hydrator registry | `apps/client/src/features/share/hydrators/`（建议新建） | 对 `drawio / excalidraw / embed` 等做按块 lazy hydrate | 交互块仅在需要时挂载 |
| FE-M4-007 | TOC 改为 DOM / payload 驱动 | `share-shell.tsx`、TOC 相关组件 | 不再依赖 `readOnlyEditorAtom` 生成目录 | 目录从 DOM headings 或 `rendered.toc` 生成 |

| FE-M4-012 | 代码块改为纯展示块 | `apps/client/src/features/share/components/shared-page-html-content.tsx`、`apps/client/src/features/share/components/shared-page-html-content.module.css` | 定义 `share-code-block` DOM 与样式；如保留复制，仅用轻量原生增强 | 代码块脱离 `readonly-code-block-view.tsx` |
| BE-M4-013 | `Mermaid` 一期按源码块降级 | `apps/server/src/core/share/share-static-renderer.service.ts` | 服务端对 `mermaid` 输出纯展示代码块，标识语言为 `mermaid`，不输出客户端绘图依赖 | 分享页含 `mermaid` 时仍稳定可读 |
| QA-M4-014 | Reader Contract 专项回归 | 回归样本、录屏、比对文档 | 覆盖固定 Reader 主题、代码块纯展示、`mermaid` 源码降级 | 满足 ACC-017, ACC-018, ACC-019 |

说明：

1. 文件名可调整，但职责必须清晰。
2. 不建议把“HTML 主渲染”、“hydrator 注册”和“legacy fallback”揉进 `shared-page.tsx` 一个文件。

### M4 验证项

1. happy path 不再创建 TipTap 只读编辑器实例。
2. 静态 HTML 与 legacy 只读渲染差异有基线对比且在允许范围内。
3. 单个交互块 hydrator 失败不影响整页正文。
4. HTML 清洗与 URL allowlist 有自动化或半自动化验证证据。
5. 分享页不再提供手动主题切换，主题样式不再依赖 palette runtime。
6. 代码块与 `mermaid` 满足纯展示 Contract，不回退到代码块 node view。

## M5：长文档首包与分段加载

### 触发条件

1. M4 已上线并稳定
2. 短文档体感已改善，但长文档首开仍慢
3. 证据显示瓶颈位于重复 payload 或整篇 HTML 一次性下发

### 任务清单

| task_id | 任务 | 目标文件 | 动作 | 完成定义 |
| --- | --- | --- | --- | --- |
| BE-M5-001 | 收敛 `page-info` 首包 | `apps/server/src/core/share/share.service.ts`、`share.controller.ts` | 静态 HTML 命中时，不再回传整份 `page.content`；`page` 收敛为最小字段 | 满足 ACC-020 |
| FE-M5-002 | 适配最小 page 契约 | `apps/client/src/features/share/types/share.types.ts`、`apps/client/src/pages/share/shared-page.tsx` | 静态 HTML 主路径只消费 `id / slugId / title / rendered`；legacy 路径按需使用 `content` | 不影响 fallback |
| BE-M5-003 | 设计分段 renderer 契约 | `apps/server/src/core/share/share-static-renderer.service.ts`、DTO | 为超长文档输出 `headHtml / nextCursor / deliveryMode` | 分段协议清晰可灰度 |
| BE-M5-004 | 新增 chunk 续传接口 | `apps/server/src/core/share/share.controller.ts`、`share.service.ts` | 增加 `POST /shares/page-segment` 或等价接口 | 后续 chunk 可按 cursor 获取 |
| FE-M5-005 | 客户端追加渲染 | `apps/client/src/features/share/components/shared-page-html-content.tsx` | 首包先渲染 `headHtml`，再在 idle / 接近底部时自动追加后续 chunk | 满足 ACC-021 |
| FE-M5-006 | 锚点与目录续传联动 | `shared-page-html-content.tsx`、TOC 组件 | 命中未加载段落时先补拉目标 chunk 再滚动 | 满足 ACC-022 |
| QA-M5-007 | 长文档专项回归 | 样本库、录屏、网络节流脚本 | 覆盖超长正文、多图文、长代码块、锚点跳转 | 长文档体验改善且无结构缺失 |

### M5 验证项

1. 静态 HTML 命中时，`page-info` 不再携带整份 `page.content`。
2. 超长文档在弱网下先出现标题与首段正文，而不是等待整篇内容。
3. 分段加载过程中无骨架反复闪烁、无整页重排。
4. 目录、锚点、重内容占位在分段模式下仍可用。

## M6：可选补偿项

### 触发条件

仅在满足以下条件时进入：

1. M4 已上线并稳定
2. M5 已完成后，正文首屏指标仍未达标
3. 证据表明新瓶颈位于服务端渲染耗时、cache 命中率或 share runtime 剩余基础包

### 任务清单

| task_id | 任务 | 目标文件 | 动作 | 完成定义 |
| --- | --- | --- | --- | --- |
| BE-M6-001 | 评估 rendered cache 策略 | renderer service / cache 层 | 比较无缓存、内存缓存、Redis 缓存收益 | 有量化结论 |
| BE-M6-002 | 可选聚合接口/字段精简 | share controller / dto / service | 仅在必要时收敛接口或压缩 payload | 减少额外 RTT 或响应体冗余 |
| FE-M6-003 | 进一步缩减 share runtime | `bootstrap-share.tsx`、`query-client.ts` 等 | 仅在数据证明必要时裁剪 Query 层或改轻量 fetch | 基础 JS 再下降 |
| QA-M6-004 | 复测与回归 | 测试用例 / 指标报告 | 验证补偿项收益与兼容性 | 指标改善且可回滚 |

### 明确不建议过早做的事项

1. 在 M4 前优先设计复杂缓存表或新聚合接口
2. 为了追求极致包体而提前打散现有 share 业务语义
3. 未建立静态 HTML 保真基线前，就直接删除 legacy 阅读路径

## 完成定义（DoD）

### 前端 DoD

1. 代码可构建
2. 分享页弱网下不白屏
3. 正常正文路径不再挂载 TipTap 只读编辑器
4. 交互块按需挂载可验证
5. 新旧实现可切换
6. 回归用例通过

### 后端 DoD

1. `page-info` 在兼容前提下返回 `rendered`
2. 鉴权逻辑不弱化
3. HTML 清洗通过安全验证
4. 前端有 fallback
5. 可回滚

## 风险提示

1. 如果只做 share 独立化和只读减重，不替换正文渲染形态，性能收益会停留在“体感改善但仍慢”的区间。
2. 如果静态 HTML 保真与安全清洗没做好，新的主路径会引入比性能更严重的线上风险。
3. 如果不保留 legacy fallback 与 feature flag，生产回滚成本会被人为抬高。
