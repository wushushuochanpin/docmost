# 分享页「下级目录打不开 / 看不到」排查清单

**最后修订**：2026-03-11  
**说明**：本文为排查用清单，非正式产品需求。实现可能已变更，请以当前代码为准。

---

## 1. 现象与可能原因

- **现象**：分享页有下级目录时，列表不显示子项，或点击子项后打不开 / 一直 loading。
- **可能原因**（按层排查）：
  1. 前端：树数据未注入、查找当前页子节点失败、链接未带 `shareId`。
  2. 后端：`pageTree` 未返回或只返回根节点、子页鉴权/归属校验失败。
  3. 环境：旧 HTML/缓存（含 dev 源码）、微信/移动端缓存导致一直 loading。

## 2. 前端排查

| 步骤 | 操作 | 预期 |
|------|------|------|
| 2.1 | 打开 DevTools → Network，进入「有下级目录」的分享页（根或子文件夹） | 存在 `POST /api/shares/page-info`（或等价 page-info） |
| 2.2 | 查看该请求响应 JSON 中的 `pageTree` | 为数组且长度 ≥ 1；当前页及其子页均应在其中（以 `id`/`parentPageId` 关联） |
| 2.3 | 若为文件夹页：查看同一响应中的 `page.id`（当前页 UUID） | 与 `pageTree` 中某条目的 `id` 一致 |
| 2.4 | 点击子项链接，看地址栏 | 应为 `/share/{shareId}/{title}-{slugId}`，且 `shareId` 非空 |
| 2.5 | 若 2.2 中 `pageTree` 正常但界面仍无子项 | 检查 `sharedTreeDataAtom` 是否被正确写入；`findSharedPageSubpages(tree, data.page.id)` 是否命中当前节点（可用 `data.page.id` 与 `node.value`/`node.slugId` 对照） |

- **关键代码**：
  - 树构建：`buildSharedPageTree`（`apps/client/src/features/share/utils.ts`）只处理同时含 `id`、`slugId` 的条目。
  - 子项查找：`findSharedPageSubpages(tree, pageId)`，`pageId` 为当前页 UUID（`data.page.id`）；支持按 `value`（UUID）、`slugId`、`id` 匹配。

## 3. 后端排查

| 步骤 | 操作 | 预期 |
|------|------|------|
| 3.1 | 同一分享下，先请求根页再请求子页的 page-info，对比两次响应的 `pageTree` | 两次的 `pageTree` 应为同一棵「分享根 + 全部后代」的扁平列表 |
| 3.2 | 子页请求：确认请求体带 `shareId` 与目标页 `pageId`（或 slugId） | 后端能通过 `getShareForPage` 找到对应 share，且子页在该 share 的子树内 |
| 3.3 | 若子页返回 404/403 | 查 `getShareForPageByShareId`、`getShareAncestorPage`：子页是否被判定为分享根的后代；`includeSubPages` 与根节点类型（file/folder）是否允许访问子页 |

- **关键逻辑**：
  - `getSharedPageTreePayload(share.pageId, ...)` 始终以**分享根**为根取整棵子树，不随当前打开的是根页还是子页变化。
  - 子页是否可访问：由 `getShareForPageByShareId` + `getShareAncestorPage` 决定。

## 4. 环境与缓存

| 步骤 | 操作 | 预期 |
|------|------|------|
| 4.1 | 分享页 HTML 响应头 | `Cache-Control: no-store`（或等效），避免 CDN/浏览器强缓存旧 HTML |
| 4.2 | 查看返回的 HTML 源码 | 不包含 `/@vite/client`、`/src/main.tsx` 等 dev 独有路径（否则为 dev 泄露，移动端易失败） |
| 4.3 | 微信 / 移动端仍一直 loading | 无痕/隐私模式或带查询串（如 `?t=1`）重开链接，排除本地缓存旧 HTML/旧脚本 |

## 5. 与「只展示直接子项」的区分

- 设计上：**文件夹主面板只展示当前页的「直接子项」**，不递归整棵树；侧边栏树可展示多级。
- 若「看不到下级目录」是因为：**点进某个文档/子页失败**（404、白屏、loading），则问题在「打开子页」的链路（鉴权、路由、前端路由/请求），而不是「目录树不展示整棵树」的设计。

## 6. 移动端只显示线框图 / 白屏的排查

- **现象**：PC 正常，微信或手机浏览器打开分享页只有骨架线框、不进入正文。
- **可能原因**：分享页 JS 分包（`bootstrap-share`）在移动端未加载完成、请求超时、或运行时报错。

### 6.1 使用分享页 Debug 模式（推荐）

1. 在分享链接后加上 `?debug=1`（例如：`https://xxx/share/xxx/yyy?debug=1`）。
2. 用**同一链接**在出问题的手机/微信里打开。
3. 页面底部会出现一块**深色调试面板**，会依次打印：
   - `Bootstrap: loading chunk...` → 表示主脚本已执行、正在加载分享页分包；
   - `Bootstrap: chunk loaded` → 分包加载成功；
   - `Bootstrap: React mounting` → React 已挂载；
   - 若出现 `Bootstrap: failed - ...` 或 `[onerror]` / `[unhandledrejection]` → 即控制台错误，可截图发给开发。
4. 若长时间只有 `Bootstrap: loading chunk...`、没有 `chunk loaded`，多为**网络或环境导致分包加载失败**（可对照 4.2、4.3 检查缓存/环境）。
5. 若出现 `API error (status): ...`，说明分包已加载，问题在**接口请求**（网络、鉴权、跨域等）。

### 6.2 用 Cursor 浏览器 MCP 看桌面端（仅作参考）

- 已安装 **cursor-ide-browser** MCP 时，可在桌面用浏览器打开分享链接，通过 MCP 工具查看：
  - `browser_console_messages`：控制台输出；
  - `browser_network_requests`：请求列表与状态码。
- 桌面环境往往正常，该方式主要用于对比「桌面无报错、移动端异常」时，确认是否为环境/设备差异。

### 6.3 手机端真实控制台（可选）

- **Android + Chrome**：手机用 Chrome 打开该页，电脑 Chrome 访问 `chrome://inspect`，连接手机后可看该页的 Console / Network。
- **iOS + Safari**：手机 Safari 打开，Mac 上 Safari 开发菜单里选该设备/页面，可看控制台。
- **微信内置浏览器**：可暂时在分享页加 `?debug=1`，依赖 6.1 的调试面板获取错误信息（无需额外工具）。

---

按 2 → 3 → 4 顺序排查，可区分是前端树/子项解析、后端 pageTree/鉴权，还是环境/缓存问题。移动端线框/白屏优先用 6.1 Debug 面板截图排查。
