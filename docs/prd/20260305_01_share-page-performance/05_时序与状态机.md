# 05 时序与状态机

**成文日期**：2026-03-05
**最后修订**：2026-03-05

本文档用于定义分享页加载时序与优化前后对比。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## 状态说明

分享页无新增业务状态机；仅加载与渲染顺序发生变化。用户可见状态仍为：未加载（白屏/skeleton）→ 密码门禁（若需要）→ 内容展示 / 错误态。

## 时序 1：As-Is 分享页加载（当前）

```mermaid
sequenceDiagram
    participant U as 用户
    participant C as Client
    participant R as Router
    participant API as Share API

    U->>C: 打开 /share/:shareId 或 /share/:shareId/p/:pageSlug
    C->>C: 加载 main.tsx + 全量 Provider + App
    C->>R: 匹配 ShareLayout / SharedPage
    Note over C: 首屏长时间白屏（无 skeleton）
    alt 仅 shareId
        C->>API: getShareById(shareId)
        API-->>C: share + sharedPage
        C->>R: navigate(/share/:shareId/p/:pageSlug)
    end
    C->>API: getShareById + getSharePageInfo
    C->>API: getSharedPageTree (ShareShell)
    API-->>C: page + tree
    C->>C: 加载 ShareShell + ReadonlyPageEditor (mainExtensions)
    C->>U: 展示内容
```

- 问题：主 bundle 重、请求串行或重复、只读编辑器重、无首屏占位。

## 时序 2：To-Be 分享页加载（目标）

```mermaid
sequenceDiagram
    participant U as 用户
    participant C as Client
    participant R as Router
    participant API as Share API

    U->>C: 打开 /share/:shareId/p/:pageSlug（或先 /share/:shareId）
    C->>C: 加载 main + 必要 Provider（或轻量 entry）
    C->>U: 1s 内展示 skeleton（标题+正文占位）
    par 并行请求
        C->>API: getShareById
        C->>API: getSharePageInfo
        C->>API: getSharedPageTree（仅需树时）
    end
    API-->>C: share + page [+ tree]
    C->>C: 按需加载 ShareShell 侧栏/TOC/Spotlight
    C->>C: 加载只读扩展子集（独立 chunk）
    C->>U: 展示正文
```

- 改进：skeleton 尽早、请求并行或合并、只读扩展独立 chunk、Shell 按需。

## 时序 3：可选合并接口

```mermaid
sequenceDiagram
    participant C as Client
    participant API as Share API

    C->>API: POST /shares/view-payload { shareId, pageSlugOrId, includeTree }
    API->>API: 鉴权 + 查 share + page + 可选 tree
    API-->>C: { share, page, pageTree? }
    C->>C: 单次响应渲染首屏
```

- 仅当后端实现合并接口时成立；前端需兼容「合并」与「现有多接口」两种模式（如通过 feature 或接口可用性检测）。
