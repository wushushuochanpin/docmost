# 05 时序与状态机

本文档用于定义分享页加载时序与优化前后对比。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

## 状态说明

分享页无新增业务状态机；变化的是“加载顺序”、“正文是否依赖编辑器运行时”以及“哪些能力可以后置”。用户可见状态调整为：

1. 进入分享页
2. 立即出现 skeleton
3. 标题与静态正文出现
4. 重内容与辅助能力渐进补齐
5. 若需要，再进入密码门禁 / 错误态 / 过期态

## 时序 1：当前真实基线（阶段一后）

```mermaid
sequenceDiagram
    participant U as 用户
    participant S as Share App
    participant API as Share API
    participant E as TipTap Readonly

    U->>S: 打开 /share/:shareId/p/:pageSlug
    S->>U: 立即出现 skeleton
    S->>API: POST /shares/page-info
    API-->>S: share + page
    S->>E: 根据 page.content 装配 readonlyExtensions
    E->>E: 解析 JSON / 创建 schema / 挂载 EditorProvider
    E-->>S: editor ready
    S->>U: 展示标题与正文
    opt 需要多页树
        S->>API: POST /shares/tree
        API-->>S: pageTree
    end
```

- 问题总结：白屏已缓解，但正文出现仍被 TipTap 只读运行时绑定。

## 时序 2：目标架构（静态 HTML 主路径）

```mermaid
sequenceDiagram
    participant U as 用户
    participant S as Share App
    participant API as Share API
    participant H as HTML Renderer

    U->>S: 打开 /share/:shareId/p/:pageSlug
    S->>U: 1s 内展示 skeleton（标题+正文占位）
    S->>API: POST /shares/page-info
    API->>H: 基于 page.content 生成 share-safe HTML
    H-->>API: rendered.html + toc + interactiveBlocks
    API-->>S: share + page + rendered
    S->>U: 直接展示标题与静态正文
    opt 需要目录
        S->>S: 从 rendered.toc 或 DOM headings 构建 TOC
    end
    opt 需要多页树
        S->>API: POST /shares/tree
        API-->>S: pageTree
    end
```

- 改进点：正文不再等待编辑器 ready；标题与首段正文能在 API 返回后直接可读。

## 时序 3：交互块渐进挂载

```mermaid
sequenceDiagram
    participant U as 用户
    participant S as Share App
    participant D as Hydrator Registry
    participant V as Viewer

    U->>S: 打开含 Drawio / Excalidraw / Embed 的分享页
    S->>U: 先显示静态正文与占位块
    opt 占位块进入视口或用户点击
        S->>D: 根据 data-share-block 查找 hydrator
        D->>V: lazy import 对应 viewer
        V-->>S: 返回完整渲染能力
        S->>U: 占位替换为真实内容
    end
```

- 用户效果：先读正文，不再因为某个图表块把整页拖慢。

## 时序 4：静态 HTML fallback

```mermaid
sequenceDiagram
    participant S as Share App
    participant API as Share API
    participant E as Legacy Readonly Editor

    S->>API: POST /shares/page-info
    API-->>S: share + page + rendered?
    alt rendered 可用且版本匹配
        S->>S: 渲染静态 HTML
    else rendered 缺失/生成失败/flag 关闭
        S->>E: 回退到 ReadonlyPageEditor
        E-->>S: legacy 正文
    end
```

- 说明：迁移期必须允许双路径并存，保证生产可回滚。

## 时序 5：可选补偿项

```mermaid
sequenceDiagram
    participant S as Share App
    participant API as Share API
    participant C as Cache

    S->>API: POST /shares/page-info
    API->>C: 按 contentHash 查询 rendered cache
    alt 命中缓存
        C-->>API: rendered payload
    else 未命中
        API->>API: 现场生成 rendered payload
        API->>C: 回填缓存
    end
    API-->>S: share + page + rendered
```

- 说明：只有当服务端生成耗时成为新瓶颈时，才进入 cache 补偿阶段。
