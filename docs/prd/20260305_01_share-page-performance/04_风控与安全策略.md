# 04 风控与安全策略

## 结论

**本需求不改变现有分享域权限与鉴权模型，但会新增一层“服务端 HTML 生成与清洗”的安全边界。**

1. 分享访问仍依赖现有 `shareId / accessToken / 密码验证 / 过期校验`；不新增凭证形态。
2. 新增风险点不在权限本身，而在“服务端返回 HTML”后带来的 XSS、危险 URL、iframe allowlist、一致性回退问题。
3. 因此，本次方案必须把“HTML 安全清洗”视为上线门槛，而不是实现细节。

## 新增安全边界

### 1) 可信输出边界

1. 只有服务端生成并清洗后的 `rendered.html` 能进入分享正文容器。
2. 前端不得接受来自 query 参数、localStorage、用户输入拼接的富文本 HTML。
3. 如果 `rendered.html` 缺失、生成失败、清洗失败，必须回退到 legacy 只读渲染路径，而不是输出未经验证的 HTML。

### 2) HTML 清洗要求

服务端必须移除或拒绝以下内容：

1. `<script>`、`<style>`、`<link rel="import">` 等不受信执行或注入能力
2. 所有 `on*` 事件处理器属性
3. `javascript:`、`data:`（除明确允许的安全图片场景外）等危险协议
4. 非 allowlist 的 `iframe`、`embed`、`object` 源地址
5. 仅编辑态使用的 DOM 标记、评论态属性、协作态元数据

### 3) URL 与资源访问控制

1. 图片、附件、媒体 URL 必须重写为 share-safe 访问地址，不能泄露仅内部可访问资源路径。
2. Embed / iframe 必须复用现有 allowlist 策略，并在服务端生成阶段再次校验。
3. 提及页链接、子页链接、附件链接的公开可访问性必须与现有 share 权限一致，不能因为 HTML 渲染而绕过权限判断。

## 交互块安全策略

1. `drawio / excalidraw / embed / video` 等交互块在 HTML 中只输出占位信息和最小数据标识，不直接输出完整可执行脚本。
2. hydrator 只根据允许的 `data-share-block` 类型动态加载前端 viewer，不执行服务端返回的任意脚本代码。
3. 单块 hydrator 失败时，只保留占位或降级链接，不允许异常传播拖垮整页正文。

## 灰度与回滚安全要求

1. 静态 HTML renderer 必须受 feature flag 控制，便于发现 XSS 或保真问题时快速全量关闭。
2. 灰度期间保留 legacy 只读编辑器渲染路径，作为安全回退。
3. 任何发现以下问题应立即触发回滚：
   - 分享页出现脚本执行或危险跳转
   - embed/iframe 源地址绕过 allowlist
   - 分享权限被削弱或资源泄露

## 合规与审计

1. 不新增权限模型，但建议新增以下日志字段：
   - `rendererVersion`
   - `renderMode`（`static-html` / `legacy-editor`）
   - `renderFallbackReason`（如有）
2. 不改变 `share-link-password-expiry` 等既有安全策略。
3. 若后续引入缓存，应确保 cache key 不会绕过权限上下文，且在内容更新后及时失效。
