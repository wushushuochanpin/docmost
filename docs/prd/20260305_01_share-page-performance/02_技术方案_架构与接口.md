# 02 技术方案：架构与接口

**成文日期**：2026-03-05
**最后修订**：2026-03-05

本文档用于定义技术架构、前端拆包与接口策略。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## As-Is 技术现状

1. **入口**：`index.html` → `main.tsx`，同步加载 Mantine 全量 CSS、i18n、PostHog、QueryClient、MantineProvider、BrowserRouter、App。
2. **分享路由**：`App.tsx` 内 `ShareLayout`（lazy）、`SharedPage`（lazy）、`ShareRedirect`（lazy）；ShareLayout 渲染 ShareShell，ShareShell 同步拉取 useGetSharedPageTreeQuery、TableOfContents、ShareSearchSpotlight、SharedTree。
3. **只读编辑器**：`ReadonlyPageEditor` 使用 `mainExtensions`（与编辑态同源），含 Collaboration、Comment、Drawio、Excalidraw、Mention、SlashCommand 等，无单独只读 Chunk。
4. **请求**：ShareRedirect 用 getShareById → navigate；SharedPage 用 getShareById + getSharePageInfo；ShareShell 用 getSharedPageTree；无合并、无预取。

## To-Be 架构原则

1. 首屏优先：skeleton 尽早展示，数据与重型组件按需/异步加载。
2. 只读路径与编辑路径分离：只读扩展独立子集 + 独立 Chunk，减少分享页首包体积。
3. ShareShell 按需：树、TOC、Spotlight 按条件或 lazy 加载，单页分享可不拉树。
4. 请求可合并/预取：在不破坏现有契约前提下，支持后端合并或前端并行预取，减少 RTT。

## 模块改造点

| 模块 | 变更点 |
| --- | --- |
| client shared-page | 增加首屏 skeleton，替代 `return <></>` |
| client share-shell | 侧栏树、TOC、ShareSearchSpotlight 改为 lazy 或按 pageTree 数量条件加载 |
| client readonly-page-editor | 引入只读扩展子集（readonlyExtensions），动态 import，主包仅保留必要展示扩展 |
| client App / 路由 | 可选：分享路由下预取 share 信息与当前页，减少串行等待 |
| server share（可选） | 可选：新增或扩展接口，一次返回 share 元数据 + 当前页内容 + 树概要 |

## 前端实现要点

### 1) 分享页首屏 Skeleton

- 位置：`apps/client/src/pages/share/shared-page.tsx`。
- 行为：当 `isLoading` 或尚无 `data` 时，渲染固定结构的 skeleton（标题条 + 若干正文占位块），不再 `return <></>`。
- 样式：与现有主题一致，占位块使用 Mantine Skeleton 或轻量 CSS，不依赖重型组件。

### 2) 只读编辑器扩展瘦身

- 新建：`readonlyExtensions`（或等价命名），仅包含文档展示必需扩展，例如：Document、Text、Paragraph、Heading、Blockquote、BulletList、OrderedList、ListItem、CodeBlock、Image、Link、Table 相关、Callout、Typography、Placeholder 等；排除 Collaboration、Comment、Drawio、Excalidraw、Mention、SlashCommand、GlobalDragHandle 等。
- ReadonlyPageEditor：通过动态 import 加载上述只读扩展与对应 Node View（若有），或通过 build 将只读扩展打到独立 chunk，首屏不加载编辑/协作相关代码。
- 兼容：若页面内容包含 Drawio/Excalidraw 等节点，可降级为占位或按需再加载对应扩展（二期可做）。

### 3) ShareShell 按需加载

- 侧栏树（SharedTree）：仅当 `data?.pageTree?.length > 1` 时请求并渲染；或将 SharedTree 与 useGetSharedPageTreeQuery 封装为 lazy 组件，首屏仅渲染 Main 区域。
- TOC（TableOfContents）：与只读编辑器同生生命周期，可保留；若体积敏感，可改为 lazy 注入。
- ShareSearchSpotlight：改为 `React.lazy` + Suspense，在用户点击搜索时再加载，或首屏后 idle 时预加载。

### 4) 请求优化（可选）

- 前端：在进入 SharedPage 且已有 shareId 时，并行发起 getShareById、getSharePageInfo、getSharedPageTree（仅当需要树时），避免 ShareRedirect → navigate 后再串行发请求。
- 后端（可选）：提供如 `GET /shares/:shareId/page-info?pageSlug=xxx&includeTree=true` 或合并现有 page-info + tree 为一次调用，减少 RTT；需保持与现有鉴权（accessToken）兼容。

## 接口契约（可选合并方案）

以下为可选后端扩展，不强制本期实现。

### 现有接口保持不变

- `POST /shares/page-info`、`POST /shares/tree`、`POST /shares/info`、`POST /shares/verify-access` 等保持契约不变。
- 若不做合并，仅通过前端并行请求与预取即可减少体感延迟。

### 可选：合并「当前页 + 树」接口

- 新接口示例：`POST /shares/view-payload` 或扩展现有某接口。
- 请求体：`{ shareId, accessToken?, pageSlugOrId, includeTree?: boolean }`。
- 响应：`{ share, page, pageTree?: [...] }`，与现有 page-info + tree 字段兼容。
- 用途：首屏一次请求拿到当前页与侧栏树，减少往返；实现时需与现有权限与 accessToken 逻辑一致。

## 构建与 Chunk 策略

- 现有 Vite 配置保持单 entry；通过动态 import 将只读扩展、ShareSearchSpotlight、可选 SharedTree 拆成异步 chunk。
- 若采用「分享轻量入口」：在 Vite 中增加第二个 entry（如 `src/share.tsx`），仅挂载分享路由所需 Provider 与路由，输出单独 bundle；部署需保证 `/share/*` 可指向该 bundle（或通过同一 bundle 内路由区分，由产品/运维决定）。
