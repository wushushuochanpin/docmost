## 需求确认结论

1. 现象：分享页在移动端（微信内置浏览器、H5）打开缓慢；生产构建比开发模式快，但仍慢。
2. 目标：缩短分享页首屏可交互时间（FCP/TTI），提升移动端体感速度。
3. 范围：仅分享域（`/share/*`）访问链路与首屏资源，不改变主站非分享路由行为。

## 关键决策

1. 优先做「首屏体验 + 减重」：skeleton、只读扩展瘦身、ShareShell 按需加载；可选分享轻量入口与接口合并。
2. 不改变分享业务语义与权限模型，与现有 share-link-password-expiry 等能力兼容。
3. 改造策略：Hybrid（在现有单入口与 ShareLayout 上做按需加载与拆包，不强制独立域名/独立 SPA 入口）。

## 非目标

1. 不引入 SSR/SSG 或服务端直出 HTML（本期仅前端优化）。
2. 不改变分享链接格式与 SEO 行为（除首屏加载方式外）。
3. 不新增数据表或分享域数据模型。
