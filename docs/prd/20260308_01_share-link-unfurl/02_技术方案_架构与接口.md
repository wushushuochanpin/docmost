# 02 技术方案：架构与接口

**成文日期**：2026-03-08 03:12:15 UTC+8
**最后修订**：2026-03-08 03:14:26 UTC+8

本文档用于定义技术架构、接口契约与兼容策略。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## As-Is 技术现状

1. `apps/server/src/core/share/share-seo.controller.ts` 已经在 `/share/:shareId/p/:pageSlug` 和 `/share/p/:pageSlug` 路由上拦截首屏 HTML，并注入 `<title>`、`og:title`、`twitter:title` 以及可选 `robots=noindex`。
2. 当前公开分享的元信息生成逻辑只覆盖标题，不覆盖摘要、图片、URL、类型、canonical。
3. 当前受限分享直接返回原始 `index.html`，不注入真实元信息，这是正确的安全基线。
4. `apps/client/src/features/page/page.utils.ts` 当前生成的分享链接为：
   - `/share/{shareKey}/p/{titleSlug}-{pageSlugId}`
   - legacy 场景可出现 `/share/p/{titleSlug}-{pageSlugId}`
5. 当前没有微信 JS-SDK 接入，也没有面向微信的分享配置接口。

## 技术结论

1. 分享卡片预览必须以服务端首屏 HTML 元信息为主，不能依赖客户端运行后再写 `<meta>`。
2. 微信增强是附加层，不是替代层：
   - 服务端元信息负责通用平台和抓取。
   - 微信 JS-SDK 负责“微信内已打开页面后”的菜单分享增强。
3. canonical URL 必须先定义清楚，再谈复制链路与 legacy 兼容。

## 目标架构

### Layer 1：Preview Meta Builder

新增统一的 preview meta 生成逻辑，输入：

- share
- page
- accessMode
- searchIndexing
- 文档标题
- 文档纯文本摘要
- 预览图 URL（如启用）

输出：

- `title`
- `description`
- `og:title`
- `og:description`
- `og:type`
- `og:url`
- `og:image`（可选）
- `twitter:card`
- `twitter:title`
- `twitter:description`
- `twitter:image`（可选）
- `canonical`
- `robots`

### Layer 2：Canonical URL Resolver

统一定义分享页规范 URL，并对历史 URL 做纠正。

推荐 canonical 路径：

```text
/share/{shareKey}/{titleSlug}-{pageSlugId}
```

说明：

1. `shareKey`：分享主键，来源于现有 `shares.key`，10 位短 key，负责定位分享实体。
2. `pageSlugId`：页面稳定标识，来源于现有 `pages.slugId`，10 位短 id，负责定位具体页面。
3. `titleSlug`：仅用于可读性和 SEO，可随标题变化；不参与主定位。
4. `legacy` 路由继续接受，但要纠正到 canonical：
   - `/share/{shareKey}/p/{titleSlug}-{pageSlugId}`
   - `/share/p/{titleSlug}-{pageSlugId}`

### Layer 3：WeChat Share Enhancer

仅在页面运行于微信内置浏览器且能力配置完成时启用。

流程：

1. 前端识别微信 UA。
2. 请求后端微信 JS-SDK 签名接口。
3. 调用 `wx.config`。
4. `wx.ready` 后调用：
   - `wx.updateAppMessageShareData`
   - `wx.updateTimelineShareData`
5. 若步骤失败，静默降级为仅依赖服务端首屏元信息。

## 公开 / 受限分享元信息策略

### 公开分享

| 字段 | 生成策略 |
| --- | --- |
| title | 文档标题，必要时截断到 80 字内 |
| description | 文档正文前若干纯文本，建议 100-140 字 |
| og:type | `article` |
| og:url / canonical | canonical 分享 URL |
| og:image | 统一品牌图或动态标题卡片图 |
| twitter:card | 有图时 `summary_large_image`，否则 `summary` |
| robots | 依据 `searchIndexing` 决定是否 `noindex` |

### 受限分享

| 字段 | 策略 |
| --- | --- |
| title | 泛化标题，如“受保护文档”或维持通用站点标题 |
| description | 不返回真实摘要 |
| image | 不返回真实封面，必要时仅使用站点通用图 |
| robots | `noindex` |
| canonical | 可返回当前 URL，但不附带真实文档语义 |

## 接口与路由设计

### 1. 首屏 HTML 注入

继续复用 `ShareSeoController`，但改造为统一消费 `PreviewMetaBuilder`。

职责：

1. 解析 incoming URL。
2. 依据 `shareKey + pageSlugId` 解析分享和页面。
3. 判断公开/受限/legacy 状态。
4. 输出 canonical redirect 或带元信息的 HTML。

### 2. canonical 路由与 legacy redirect

建议新增并对外主推：

```text
GET /share/:shareKey/:pageSlug
```

其中：

- `pageSlug = {titleSlug}-{pageSlugId}`

兼容行为：

1. 请求 legacy `/share/:shareKey/p/:pageSlug` 时：
   - 若是公开分享，301 或 302 到 canonical 路径。
2. 请求 `/share/p/:pageSlug` 时：
   - 仅在 legacy 兼容策略允许时解析。
   - 解析成功后重定向到 canonical 路径。
3. 请求 canonical 路径但 `titleSlug` 不匹配时：
   - 仍按 `pageSlugId` 成功解析页面。
   - 再重定向到标准 canonical URL。

### 3. 微信 JS-SDK 配置接口

新增接口建议：

```json
GET /api/shares/wechat-signature?url={currentUrl}
```

响应：

```json
{
  "appId": "wx123",
  "timestamp": 123456,
  "nonceStr": "abc",
  "signature": "xyz"
}
```

约束：

1. 仅在环境变量配置完整且域名在微信允许范围内时启用。
2. 接口不返回任何额外业务敏感信息。
3. 前端仅在微信 UA 下调用。

## 复制链接策略

1. 所有“复制分享链接”入口统一生成 canonical URL。
2. 统一使用同一个 builder，避免：
   - 页面内复制一套路径
   - SEO 输出一套路由
   - 微信分享再一套路由
3. 复制出来的 URL 仍包含稳定 key 和页面短 id，不改为纯标题 URL。

## 预览图策略

### 一期

1. 可以先使用站点统一默认分享图。
2. 若公开分享存在标题，则图上可渲染标题，但不要求首期一定做动态图服务。

### 二期

1. 评估生成动态 OG Image：
   - 标题
   - 站点名
   - 可选图标
2. 生成形式可为边缘函数、服务端图片接口或预生成缓存。

## 失败与降级策略

1. Preview Meta Builder 异常：
   - 回退到当前最小实现，仅保留 `<title>` 或返回原始 `index.html`
2. canonical 解析失败：
   - 不做错误重定向，回退到当前可访问路径
3. 微信 JS-SDK 签名失败：
   - 页面正常渲染，不阻塞正文和分享页访问
4. 预览图生成失败：
   - 回退到默认站点图，不阻塞卡片标题与摘要

## 兼容性与实现顺序

1. 先补全服务端元信息字段。
2. 再统一 canonical URL builder 和 redirect。
3. 最后接入微信 JS-SDK 菜单分享增强。

这是正确顺序。反过来先做微信 JS-SDK，没有服务端元信息和 canonical 规范，收益会很散，也无法覆盖最常见的“直接粘贴链接”链路。
