## 结论

一期不新增数据库表，也不改变现有 `shares` 与 `pages` 主数据结构。  
本专题以“复用现有主键 + 衍生 preview metadata + URL 规范”完成，不把“分享预览”误做成一套新的持久化模型。

## 现有可复用字段

| 实体 | 字段 | 用途 |
| --- | --- | --- |
| shares | `key` | 10 位短 key，作为 canonical URL 的分享主键 |
| shares | `accessMode` | 决定公开/受限预览策略 |
| shares | `searchIndexing` | 决定 `robots=noindex` 策略 |
| pages | `slugId` | 10 位短 id，作为 canonical URL 中的页面稳定标识 |
| pages | `title` | 生成 preview title 与 title slug |
| pages | `content` 或渲染后的纯文本 | 生成公开分享 description |

## 衍生数据定义

以下字段为运行时派生，不落库：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `previewTitle` | `page.title` | 截断与清洗后的展示标题 |
| `previewDescription` | `page.content` 提取纯文本 | 公开分享摘要 |
| `canonicalPath` | `share.key + page.slugId + titleSlug` | 规范化分享路径 |
| `previewImageUrl` | 统一静态图或动态图服务 | 分享卡片图 |

## 配置项建议

本专题更依赖配置，不依赖表结构迁移。建议引入或确认以下环境配置：

| 配置项 | 作用 | 是否必需 |
| --- | --- | --- |
| `APP_URL` / 对外基准域名 | 生成 `og:url` 与 canonical | 是 |
| `SHARE_PREVIEW_IMAGE_URL` | 默认分享图 | 否 |
| `WECHAT_SHARE_ENABLED` | 控制微信增强开关 | 否 |
| `WECHAT_APP_ID` | 微信 JS-SDK 配置 | 仅微信增强需要 |
| `WECHAT_APP_SECRET` 或签名能力配置 | 微信 JS-SDK 签名 | 仅微信增强需要 |

## 为什么一期不落库

1. 标题、摘要、URL 都可由现有分享和页面数据稳定派生。
2. 提前落库“分享标题/摘要/图片”会把简单问题复杂化，并引入一致性问题：
   - 文档标题改了，预览是否同步？
   - 文档内容变了，摘要如何失效？
3. 只有当后续明确需要“手动自定义每个分享卡片”时，才值得引入持久化字段。

## 二期可能扩展

仅在明确有收益时再评估：

1. 预览图缓存键：
   - `shareKey + pageSlugId + updatedAt`
2. 自定义分享卡片字段：
   - `customPreviewTitle`
   - `customPreviewDescription`
   - `customPreviewImage`

当前阶段不建议提前设计这些字段。
