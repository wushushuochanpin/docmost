## 需求确认结论

1. Web 端不能直接把内容“发给微信好友”或“发朋友圈”；桌面端正确做法是二维码把用户带到微信里。
2. 交互必须按环境分流：
   - 桌面浏览器：展示二维码
   - 微信内浏览器：提示使用微信右上角原生分享
   - 手机非微信浏览器：以复制链接为主
3. 本专题不解决“所有微信聊天场景都完美卡片化”，那属于 `share-link-unfurl` 专题。
4. 本专题的目标是把“用户怎么从 Web 端进入微信分享链路”做清楚、做顺手、做不误导。

## 关键决策

1. 不用误导性按钮文案，例如“直接分享到朋友圈”。
2. 桌面端“微信分享”按钮的真实行为是：展示二维码，并明确说明“扫码后再用微信原生菜单分享”。
3. 微信内 H5 不展示二维码，只展示原生分享引导。
4. 密码分享不提供二维码主路径；二维码只适用于公开链接。

## 非目标

1. 不提供桌面网页一键直发微信好友/朋友圈能力。
2. 一期不实现公众号后台、微信签名和 JS-SDK 完整接入闭环。
3. 不改变现有分享权限模型。
