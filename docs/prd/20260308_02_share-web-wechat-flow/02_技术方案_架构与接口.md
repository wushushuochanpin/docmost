## As-Is 技术现状

1. 分享弹窗逻辑集中在 `apps/client/src/features/share/components/share-modal.tsx`。
2. 当前分享链路已能生成 canonical 分享链接。
3. 项目依赖中已存在 `qrcode`，可直接在客户端生成二维码图片。
4. 当前没有微信 UA 分流逻辑，也没有微信专属交互组件。

## 方案分层

### Layer 1：环境识别

前端根据运行环境分三类：

1. `desktop_browser`
2. `mobile_wechat_webview`
3. `mobile_non_wechat`

建议判定：

- `isMobile`: `matchMedia("(max-width: 48em)")`
- `isWechat`: `navigator.userAgent` 包含 `MicroMessenger`

### Layer 2：分享弹窗面板

新增独立组件，例如 `ShareWechatPanel`：

输入：

- `shareLink`
- `copyValue`
- 当前环境

输出：

- 桌面二维码
- 微信内引导文案
- 手机非微信复制引导

### Layer 3：二维码生成

1. 仅在 `desktop_browser + public_share` 条件下生成二维码。
2. 使用 `qrcode.toDataURL()` 异步生成。
3. 生成失败时静默降级为普通复制链接。

## 一期技术约束

1. 一期不接微信 JS-SDK。
2. 一期不新增服务端接口。
3. 一期不新增数据库字段。
4. 一期仅改分享弹窗交互层。

## 二期扩展位

当环境配置完成后，再新增：

1. 微信签名接口
2. 前端 `wx.config`
3. `updateAppMessageShareData`
4. `updateTimelineShareData`

注意：二期也只是“增强分享内容”，不是替用户自动发朋友圈。
