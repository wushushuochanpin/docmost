# 02 技术方案：架构与接口

**成文日期**：2026-03-04 22:50:29 UTC+8
**最后修订**：2026-03-04 23:14:30 UTC+8

本文档用于定义技术架构、接口契约与兼容策略。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## As-Is 技术现状

1. 匿名公开读取核心入口为 `POST /shares/page-info`，当前主要按 `pageId` 推导 share。
2. 公开页路由同时支持带 `shareId` 与不带 `shareId` 的路径。
3. `shares` 表无密码/过期字段，服务端没有受限访问门禁。
4. 公开搜索 `POST /search/share-search` 未绑定“密码校验通过”上下文。

## To-Be 架构原则

1. 受限分享访问以 `shareId` 为主键边界，不再依赖仅 `pageId` 兜底。
2. 公开读取链路统一前置 `ShareAccessGate` 校验。
3. 密码只做哈希存储与比较，不做明文传递与落日志。
4. 过期判定以服务端当前时间为准。
5. “不记住密码”实现为“无持久化登录态，仅页面生命周期内可用的内存访问令牌”。
6. 错误返回必须可区分，但不泄露额外资源信息。

## 模块改造点

| 模块 | 变更点 |
| --- | --- |
| `core/share` | 新增受限分享字段处理、访问门禁、重建链接接口 |
| `core/search` | `share-search` 增加受限门禁校验 |
| `core/share/share-seo.controller.ts` | 对受限分享不注入页面 SEO 元信息 |
| `client share modal` | 新增受限模式 UI、密码与有效期配置 |

## 接口契约（目标）

### 1) 创建分享

`POST /shares/create`

请求体新增字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pageId` | string | 是 | 页面 ID |
| `includeSubPages` | boolean | 否 | 与现有一致 |
| `searchIndexing` | boolean | 否 | 与现有一致 |
| `accessMode` | `public`\|`password_expiring` | 否 | 默认 `public` |
| `password` | string | 条件必填 | `accessMode=password_expiring` 时必填 |
| `expiresInMinutes` | number | 条件必填 | `1..30`，仅受限模式 |

响应新增字段：

| 字段 | 说明 |
| --- | --- |
| `accessMode` | 分享模式 |
| `expiresAt` | 过期时间 |
| `isExpired` | 是否过期（派生字段） |

### 2) 更新分享

`POST /shares/update`

规则：

1. 保留现有 `includeSubPages/searchIndexing` 更新能力。
2. 不允许通过该接口延长已过期受限链接。
3. 安全敏感字段修改（密码、有效期）统一走“重建链接”接口。

### 3) 重建受限分享（新增）

`POST /shares/regenerate-protected`

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `shareId` | string | 是 | 旧分享 ID |
| `password` | string | 是 | 新密码 |
| `expiresInMinutes` | number | 是 | `1..30` |

行为：

1. 创建新 `share.key`。
2. 旧链接立即失效。
3. 返回新链接和新 `expiresAt`。

### 4) 验证受限访问（新增）

`POST /shares/verify-access`

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `shareId` | string | 是 | 分享 ID/Key |
| `password` | string | 是 | 用户输入密码 |

成功响应：

| 字段 | 说明 |
| --- | --- |
| `accessToken` | 短期访问令牌（仅客户端内存保存） |
| `expiresAt` | 分享到期时间 |

### 5) 公开读取接口收敛

收敛接口：

1. `POST /shares/page-info`
2. `POST /shares/tree`
3. `POST /shares/info`
4. `POST /search/share-search`

统一规则：

1. 请求必须包含 `shareId`。
2. 当 `accessMode=password_expiring` 时必须带有效 `accessToken`。
3. 若 `shareId` 与页面不匹配，返回 `404`（避免泄露存在性）。

## 错误码契约（细化版 v1）

### 错误响应结构

```json
{
  "statusCode": 410,
  "code": "SHARE_EXPIRED",
  "message": "Share link has expired"
}
```

### 错误码清单

| HTTP | code | 触发条件 | 前端文案 | retryable |
| --- | --- | --- | --- | --- |
| 401 | `SHARE_PASSWORD_REQUIRED` | 受限分享未提供访问凭证 | 请输入密码 | 是 |
| 401 | `SHARE_PASSWORD_INVALID` | `verify-access` 密码错误 | 密码错误 | 是 |
| 401 | `SHARE_ACCESS_TOKEN_INVALID` | 访问令牌无效、伪造或版本不匹配 | 请重新输入密码 | 是 |
| 404 | `SHARE_NOT_FOUND` | `shareId` 不存在或不属于当前页面 | 链接不存在 | 否 |
| 410 | `SHARE_EXPIRED` | `now >= expiresAt` | 链接已过期 | 否 |
| 400 | `SHARE_TTL_INVALID` | 创建/重建有效期不在 `1..30` | 有效期需在 1-30 分钟 | 是 |
| 400 | `SHARE_PASSWORD_INVALID_FORMAT` | 密码不满足最小格式策略 | 密码格式不符合要求 | 是 |
| 409 | `SHARE_REGENERATE_REQUIRED` | 对已过期受限分享执行 update 延长 | 链接已过期，请重新生成 | 否 |
| 429 | `SHARE_VERIFY_RATE_LIMITED` | 验证接口触发限流 | 操作过于频繁，请稍后再试 | 是 |
| 403 | `SHARE_ACCESS_MODE_FORBIDDEN` | 非受限接口调用了受限路径（保留码） | 当前分享模式不支持该操作 | 否 |

### 错误判定优先级（避免歧义）

1. 先校验 `shareId` 合法性与存在性，不存在直接 `404`。
2. 若存在且过期，优先返回 `410`。
3. 若未过期，判定访问凭证是否存在/有效（`401`）。
4. 仅 `verify-access` 才可能出现 `SHARE_PASSWORD_INVALID`。
5. 禁止在错误详情中返回页面标题、空间信息等可枚举字段。

### 前端映射约束

1. 以 `code` 为准，不以 `message` 字符串匹配。
2. `SHARE_EXPIRED` 展示 CTA：`重新生成链接（仅发起人可见）`。
3. `SHARE_PASSWORD_INVALID` 支持用户重试，不跳转 404。
4. `SHARE_NOT_FOUND` 进入 404 页，不显示密码框。

## 路由下线策略（细化版）

### 现状与目标

1. 现状双路由：`/share/:shareId/p/:pageSlug` 与 `/share/p/:pageSlug`。
2. 目标单路由：仅保留 `shareId` 版本，避免 pageSlug 推导导致弱绑定。

### 分阶段计划（PRD 锁定）

| 阶段 | 日期（建议） | 策略 | 开关/控制位 | 退出门槛 |
| --- | --- | --- | --- | --- |
| R0 | 2026-03-04 | 契约冻结，仅文档与埋点准备 | `SHARE_LEGACY_ROUTE_MODE=observe` | 错误码与埋点定义评审通过 |
| R1 | 2026-03-05 ~ 2026-03-11 | 仅观测旧路由流量，不改变行为 | `observe` | 收集 7 天基线访问量 |
| R2 | 2026-03-12 ~ 2026-03-18 | 受限分享在旧路由硬拦截（404） | `protected_block` | 受限链路绕过访问成功=0 |
| R3 | 2026-03-19 ~ 2026-03-25 | 普通分享旧路由 302 到标准路由 | `redirect_public` | 旧路由流量降到 <5% |
| R4 | 2026-03-26 起 | 移除 `/share/p/:pageSlug` 路由 | `removed` | 回滚窗口结束后稳定 7 天 |

### 回滚锚点（路由专项）

1. 运行时开关可从 `removed` 降回 `redirect_public`。
2. 若出现大规模外部链接失效，可临时恢复 R3，不恢复受限分享旧路由访问。
3. 回滚后必须保留审计日志，用于识别失效来源。

## 前端状态管理约束

1. `accessToken` 仅可保存在内存状态（React state/atom），禁止 localStorage/sessionStorage/cookie 持久化。
2. 页面刷新、关闭、重新打开后，必须重新输入密码。
3. 请求失败依据 `code` 精确提示，不使用模糊“访问失败”。

## 性能与稳定性

1. 密码校验使用 `bcrypt.compare`，并限制单 IP + 单 shareId 的尝试频率。
2. 过期判断在服务端执行，不依赖客户端时间。
3. 门禁校验应在读取页面内容与树之前执行，避免无效重查询。

## PRD 阶段完成定义（DoD）

1. 错误码清单、优先级、前端映射三方评审通过。
2. 路由下线阶段、开关位、回滚锚点评审通过。
3. 测试矩阵覆盖所有错误码与全部路由阶段。
