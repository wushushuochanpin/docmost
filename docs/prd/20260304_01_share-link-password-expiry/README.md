## 需求确认结论（用户明确确认）

1. 有效期起点：创建分享时开始计时。
2. 过期语义：链接过期（产品文案可显示为“链接已过期”）。
3. 过期后不可续期：必须重新生成新链接。
4. 不记住密码：不允许持久化“已验证”状态。
5. 模式策略：新增“受限分享模式”，保留现有公开分享模式。
6. 子页面策略：继承同一密码与同一过期时间。
7. 路由策略：采用带 `shareId` 的链接作为安全基线。
8. 错误提示：允许区分“密码错误 / 链接已过期 / 链接不存在”。

## 关键批判性结论（拒绝迎合）

1. 核心诉求不是“加密码”而是“可控失效 + 防扩散 + 可审计”。
2. 只在前端做倒计时没有安全价值，必须服务端强校验过期。
3. 若继续允许无 `shareId` 路由，会弱化链接绑定边界，不符合“更安全合规”的目标。
4. “不记住密码”如果被实现为“每个 API 都输一次密码”，可用性会崩坏，必须设计成“仅页面内短期内存态凭证、刷新即失效”。

## 关键决策

1. 采用 `public` 与 `password_expiring` 双模式，不推翻现有分享域模型。
2. 受限模式最大 TTL 为 30 分钟，且由后端计算 `expiresAt`，不信任前端输入时间戳。
3. 受限模式必须通过 `shareId` 访问与鉴权，避免按 `pageId` 兜底造成越界。
4. 过期后不允许“延长”同一链接，必须重新生成（新 `share.key` + 新密码）。
5. 错误码采用契约化管理：`status + code + message`，以前端 `code` 映射为准。
6. 旧路由 `/share/p/:pageSlug` 按 R1~R4 分阶段下线，并保留阶段回滚锚点。

## 非目标

1. 不实现下载口令、短信验证码、一次性密码等更复杂安全体系。
2. 不改变空间级/工作区级“是否允许公开分享”的已有治理逻辑。
3. 不在本期引入完整 WAF 或设备指纹风控系统。
