## 实施阶段

### 阶段 A：后端与数据层

1. 增加 `shares` 新字段与迁移。
2. 扩展 DTO 与 repo 字段映射。
3. 新增 `verify-access`、`regenerate-protected` 接口。
4. 统一公开读取接口门禁，强制 `shareId` 校验（受限模式）。
5. 增加错误码与审计事件。

### 阶段 B：前端交互与路由

1. 分享弹窗新增“受限分享”配置项（密码 + 分钟）。
2. 公开页新增密码输入门禁与错误态页面。
3. 受限模式访问请求注入内存态访问令牌。
4. 旧路由 `/share/p/:pageSlug` 的受限访问直接拦截。
5. 普通分享旧路由按阶段重定向到标准路径。

### 阶段 C：联调与灰度

1. 开启受限模式灰度开关（workspace 维度）。
2. 小流量验证创建、访问、过期、重建主链路。
3. 扩大灰度并观察错误码、失败率与旧路由流量。

## 错误码专项验收门槛

1. 错误码覆盖率：所有定义 code 均有自动化用例。
2. 错误映射一致性：前端文案与 code 一一对应，无 message 兜底匹配。
3. 线上灰度期间 `unknown_error` 比例 < 0.5%。

## 路由下线专项门槛

| 阶段 | 指标 | 门槛 |
| --- | --- | --- |
| R1 -> R2 | 旧路由访问基线采集完整度 | >= 7 天连续数据 |
| R2 -> R3 | 受限分享旧路由绕过成功次数 | 0 |
| R3 -> R4 | 旧路由流量占比 | <5% 且连续 7 天下降 |

## 回归范围

1. 普通公开分享链路（不应回归破坏）。
2. 分享列表、分享开关、子页面分享继承。
3. 分享页树加载、分享内搜索、SEO 渲染。
4. 工作区/空间级“禁用公开分享”开关行为。

## 监控与发布门槛

| 指标 | 门槛 | 触发动作 |
| --- | --- | --- |
| `verify-access` 5xx 比例 | >1% 持续 5 分钟 | 暂停灰度 |
| `SHARE_PASSWORD_INVALID` 峰值 | 超历史 3 倍 | 启动风控排查 |
| 受限分享访问 P95 | >800ms 持续 10 分钟 | 性能降级或回滚 |
| 旧路由 404 投诉量 | 超历史均值 2 倍 | 暂缓推进下线阶段 |

## 回滚策略

### 回滚锚点

1. 锚点 1：后端 feature flag 关闭受限模式入口。
2. 锚点 2：前端隐藏受限模式 UI，仅保留普通公开分享。
3. 锚点 3：门禁逻辑回退到旧公开读取策略（临时）。
4. 锚点 4：路由阶段开关回退（`removed -> redirect_public -> protected_block`）。

### 回滚步骤

1. 先关前端入口，防止新增受限分享继续写入。
2. 再回退后端门禁逻辑，恢复公开访问可用性。
3. 对路由异常优先回退路由阶段，不直接回滚 DB 变更。
4. 保留数据库新增字段，不做紧急删字段操作。
5. 故障恢复后再评估二次发布。

## 风险与缓解

| 风险 | 描述 | 缓解措施 |
| --- | --- | --- |
| UX 过严导致投诉 | 不记住密码会增加输入成本 | 明确提示“刷新后需重新输入” |
| 旧链接不可用 | 无 `shareId` 路由被限制 | 给出迁移公告和重建入口 |
| 实现遗漏链路 | 某接口未接入门禁 | 联调阶段执行全链路清单验收 |
| 错误码漂移 | 后端 code 与前端映射不一致 | 增加 contract test 与 CI 校验 |
