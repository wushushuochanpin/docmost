## 核心设计理念：基于纯 CSS 的图案生成引擎

为了兼顾性能、打包体积和对于深色模式（Dark Mode）的完美适配，前端文档画布的底纹实现**坚决摒弃切图 (PNG/JPG/SVG 文件实体)**。

### 前端双层结构设计（分离颜色与纹理）

文档编辑器的外层容器 `.editor-wrapper` 必须剥离为“颜色层”与“底纹层”。
- **底层 (Color Layer)**：通过 React 绑定 `style={{ backgroundColor: var(--theme-color-xxx) }}` 或注入对应的 CSS 类名，控制文档的纯色背景。
- **上层伪元素 (Pattern Layer)**：利用 `.editor-wrapper::before` 或绝对定位空 `div` 层铺满背景，作为**纯 CSS 纹理层**。
  - 通过 CSS `linear-gradient` / `radial-gradient` 算法绘制网格或点阵。
  - 通过 `opacity` 或 `mix-blend-mode: multiply` 与下方的纯色进行自然融合。
  - 优点：无需给每种颜色预写一套对应的底纹，矩阵组合复用率高。

### CSS 底纹代码实现标准（示例）

```css
/* 点阵 */
.pattern-dots {
  background-image: radial-gradient(circle, rgba(0, 0, 0, 0.08) 1px, transparent 1px);
  background-size: 20px 20px;
}

/* 网格 */
.pattern-grid {
  background-image: 
    linear-gradient(to right, rgba(0, 0, 0, 0.04) 1px, transparent 1px),
    linear-gradient(to bottom, rgba(0, 0, 0, 0.04) 1px, transparent 1px);
  background-size: 24px 24px;
}
```

## 接口契约：文档保存与拉取

该功能直接复用现有的文档详情读取 API 与文档保存/更新 API。后端无需专门新增“修改背景特化接口”，仅需在 Payload 的扩展字段中支持该元数据。

### 请求/响应模型扩展

**GET /api/v1/documents/:id**
**PUT /api/v1/documents/:id**

Body 载荷扩展（或者放入已有的 `meta` / `properties` JSON 字段中）：
```json
{
  "properties": {
    "theme_color": "green",  // 务必使用具有语义的枚举常量（如 white, green, yellow），禁止保存 Hex 颜色值
    "theme_pattern": "dots"  // 纹理枚举：blank, dots, grid, lines
  }
}
```

*注：*禁止保存如 `#FCFBE7` 的十六进制码，因为前端需要根据语义 `yellow` 在“日间模式”和“夜间深色模式”下映射两套截然不同的真实表现色值。

## 深色模式降级策略 (Dark Mode Fallback)

文档工具对可读性要求极高。当处于 Dark Mode 且 API 下发的 `theme_color` 不是 `white` 时，必须采取降级渲染：
1. **策略 A（推荐）**：强行无视 `theme_color`，所有底色收敛为默认暗灰色（仅显示其选择的底纹 `theme_pattern`）。
2. **策略 B**：在 CSS 变量域定义 `[data-theme='dark']` 下极度保守的暗色相（如幽暗绿、幽暗黄），确保对比度达标。
