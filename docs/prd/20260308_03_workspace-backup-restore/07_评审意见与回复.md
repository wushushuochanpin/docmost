## 评审结论摘要

1. 采纳“工作区级自助备份/恢复”定位。
2. 明确拒绝“把现有整库 `pg_dump` 自动化后包装成工作区备份”。
3. 明确 V1 恢复到新工作区，不做原地覆盖。

## 争议点与治理结论

### 争议 1：是否继续沿用 `pg_dump`

- 反对意见：`pg_dump` 实现快，能先上线。
- 治理结论：如果目标是工作区级恢复到新工作区，`pg_dump` 不是快方案，而是错误方案；后续所有恢复语义都会被拖垮。

### 争议 2：是否为了体验做原地恢复

- 反对意见：恢复到新工作区会让用户多一步确认与切换。
- 治理结论：这一步是风险隔离换来的必要成本。恢复功能的第一目标是“不要误伤原数据”，不是“操作步数最少”。

### 争议 3：是否先只做自动备份，不做恢复

- 反对意见：恢复链路复杂，可后置。
- 治理结论：若没有 dry-run 与恢复记录，备份能力会停留在“看起来在做事”，不满足用户已经明确的核心诉求。
