- 交付模式：package_dir

## 存储路径与命名规范

- root_path：docs/prd
- package_name：20260308_03_workspace-backup-restore

## 交付目标

1. 让研发可以直接按任务单分工，不再从 PRD 反向拆需求。
2. 明确哪些任务可以并行，哪些必须串行。
3. 提前锁死高风险交互：恢复按钮不是一键恢复。

## 研发角色与分工

| 角色 | 负责范围 | 不负责范围 |
| --- | --- | --- |
| 后端 A | 数据迁移、Policy API、调度、作业状态机 | 前端交互 |
| 后端 B | 逻辑快照导出、COS 产物、恢复 dry-run/apply | 页面实现 |
| 前端 A | 设置页改版、策略配置、作业列表增强 | 恢复服务端逻辑 |
| 前端 B | 恢复向导、恢复记录列表、状态反馈 | 后端产物格式 |
| QA | 用例编写、联调验证、恢复演练、回归 | 需求边界变更决策 |
| 运维/SRE | COS 权限、环境变量、监控告警、压测支持 | 业务页面实现 |

## 后端任务单

### BE-01 数据迁移与类型更新

目标：

1. 补齐 `backup_policies`、`backup_jobs`、`backup_restores` 所需字段
2. 更新 Kysely types / DTO / service types

子任务：

1. 新增 `schedule_kind`、`schedule_config`、`next_run_at`
2. 新增 `scope_type`、`artifact_driver`、`package_format_version`
3. 新增 `source_type`、`source_job_id`、`source_upload_id`、`target_workspace_name`、`target_workspace_id`
4. 增加索引与唯一约束

完成定义：

1. 迁移可在空库与现网库执行
2. 旧手动作业不报错

### BE-02 Policy API 与调度器

目标：

1. 实现单工作区单策略
2. 实现分钟级 due policy 轮询

子任务：

1. `GET /backups/policy`
2. `PUT /backups/policy`
3. `nextRunAt` 计算器
4. 分布式锁
5. `schedule` 类型作业入队

完成定义：

1. 同一工作区不会重复产生自动任务
2. UI 可读取并保存策略

### BE-03 工作区级逻辑快照导出

目标：

1. 定义工作区级备份包格式
2. 导出纳入范围的数据域与附件

子任务：

1. 生成 `manifest.json`
2. 生成 `summary.json`
3. 生成 `SHA256SUMS`
4. 导出 `workspace/spaces/pages/page_history/comments/backlinks/attachments`
5. 导出 actor 最小快照

完成定义：

1. 包结构稳定
2. 生成的 `checksum` 可校验通过

### BE-04 COS 产物与下载

目标：

1. 接入腾讯 COS 作为主存储
2. 成功作业可下载到本地
3. 支持受控删除历史备份产物

子任务：

1. 产物上传
2. 短时效下载 URL
3. retention 清理
4. legacy 作业与新作业区分
5. `POST /backups/jobs/:id/delete-artifact`
6. 删除前置校验：不得删除最后一个可用成功备份，不得删除被恢复流程引用的备份
7. 删除后写审计日志并保留作业记录

完成定义：

1. 成功任务可下载
2. 过期或缺失产物会报明确错误
3. 已删除产物的作业仍可查询，但不可下载、不可恢复

### BE-05 dry-run 恢复

目标：

1. 支持从成功作业或上传包执行 dry-run
2. 输出恢复报告

子任务：

1. `POST /backups/uploads`
2. `POST /backups/restores` dry-run 模式
3. manifest/checksum/schema 校验
4. 目标工作区名冲突校验
5. 用户映射报告

完成定义：

1. dry-run 不落业务数据
2. 失败原因对前端可读

### BE-06 apply 恢复到新工作区

目标：

1. 通过成功 dry-run 后，允许正式恢复
2. 创建新工作区并完成内容恢复

子任务：

1. apply 前置校验
2. 新工作区创建
3. sourceId -> targetId 映射
4. spaces/pages/comments/backlinks/page_history 恢复
5. 附件对象恢复
6. 恢复报告写回

完成定义：

1. 原工作区不变
2. 新工作区可进入并看到恢复内容

## 前端任务单

### FE-01 设置页重构

目标：

1. 把现有备份页从“手动作业页”升级为“策略 + 作业 + 恢复”入口

子任务：

1. 增加边界说明文案
2. 增加概览卡片
3. 保持现有作业表格能力不回归

### FE-02 自动备份策略卡片

目标：

1. 支持启停、频率、固定时间、时区、保留规则配置

子任务：

1. 表单建模
2. 预设频率交互
3. 保存成功/失败反馈
4. 下次执行时间展示

### FE-03 作业列表增强

目标：

1. 展示新字段，支持下载与恢复入口
2. 对可删除的历史备份提供受控删除入口

子任务：

1. 展示 `triggerType`、`checksum`、摘要、错误原因
2. 对 legacy 作业展示只读/仅下载标识
3. `success` 作业显示下载按钮
4. `success` 的新格式作业显示恢复按钮
5. 在更多操作中为可删除的历史成功备份显示“删除备份”
6. 已删除产物展示“产物已删除”状态，并禁用下载/恢复

### FE-04 恢复向导

目标：

1. 点击“恢复”按钮进入恢复流程，而不是直接恢复

子任务：

1. 恢复源确认
2. 目标工作区名称输入
3. 范围与排除项说明
4. dry-run 按钮
5. dry-run 结果展示
6. apply 二次确认

完成定义：

1. 点击恢复按钮不创建工作区
2. 只有 apply 成功后才出现新工作区入口

### FE-05 恢复记录列表

目标：

1. 可查看历史 dry-run / apply 记录、状态与结果摘要

子任务：

1. 列表查询
2. 失败态说明
3. 成功后进入新工作区的跳转入口

## 联调顺序

### Step 1：数据库与类型先行

前置：

1. BE-01 完成

联调结果：

1. 前后端共享字段与枚举稳定

### Step 2：策略接口与页面表单联调

前置：

1. BE-02 完成
2. FE-02 完成基础表单

联调检查：

1. 单策略读写正确
2. `nextRunAt` 展示正确

### Step 3：新作业列表字段联调

前置：

1. BE-03, BE-04 完成基础返回
2. FE-03 完成表格改造

联调检查：

1. 手动/自动状态一致
2. 下载链接可用
3. legacy 作业正确降级
4. 历史备份删除后状态刷新正确

### Step 4：恢复 dry-run 联调

前置：

1. BE-05 完成
2. FE-04 完成 dry-run 流程

联调检查：

1. 点击恢复按钮只打开向导
2. dry-run 报告字段齐全
3. 异常包能给出明确错误

### Step 5：恢复 apply 联调

前置：

1. BE-06 完成
2. FE-04 完成 apply 确认流
3. FE-05 完成恢复记录页

联调检查：

1. apply 前必须存在成功 dry-run
2. apply 成功后新工作区生成
3. 原工作区不变

## 测试执行顺序

### QA-01 接口级测试

1. Policy API
2. Job list API
3. Download URL API
4. Restore API

### QA-02 页面级测试

1. 策略卡片
2. 作业列表
3. 恢复向导
4. 恢复记录列表

### QA-03 端到端链路测试

1. 手动备份 -> 下载
2. 自动备份 -> 下载
3. 作业恢复 dry-run
4. 作业恢复 apply
5. 上传包恢复 dry-run / apply

### QA-04 风险专项测试

1. legacy 包拒绝恢复
2. 破损包拒绝恢复
3. 目标工作区名冲突
4. 同工作区并发备份
5. 同工作区并发恢复
6. 最后一个可用成功备份不可删除
7. 被 dry-run / apply 引用的备份不可删除

## 串行依赖与并行边界

### 必须串行

1. 数据迁移先于所有联调
2. 包格式冻结先于 dry-run 开发
3. dry-run 完成先于 apply 开发

### 可以并行

1. BE-02 与 FE-02 可并行
2. BE-03 与 FE-03 的 UI 改造可并行
3. QA 可在 FE/BE 联调前先写测试用例和脚本

## 阻塞点清单

| 阻塞点 | 会卡住谁 | 建议处理方式 |
| --- | --- | --- |
| 包格式迟迟不冻结 | BE-05、BE-06、FE-04、QA | 在 M0 结束前完成冻结 |
| COS 权限未配置 | BE-04、QA、运维 | 在联调前先做环境检查 |
| 恢复范围反复变更 | 全员 | 纳入 / 排除清单一旦冻结，不在 M3 后再扩大 |

## Definition of Done

1. 前端页面可完成策略配置、手动备份、下载、受控删除历史备份、恢复向导、恢复记录查看。
2. 后端可完成自动备份、COS 产物存储、dry-run 和 apply 恢复。
3. 至少 3 次真实恢复演练通过。
4. 恢复按钮不会触发一键恢复。
5. 删除历史备份后，记录与审计信息保留，产物不可再下载或恢复。
