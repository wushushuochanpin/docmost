### Phase 0：纠偏与打底

目标：

1. 明确页面 scope 文案
2. 识别 legacy 整库作业
3. 补齐 `checksum` 与 `metadata.summary` 规范

交付：

1. 页面增加“工作区级备份，不等同实例灾备”说明
2. 后端任务详情带 `scopeType` / `packageFormatVersion`

### Phase 1：自动策略与工作区级逻辑快照

目标：

1. 上线单策略配置
2. 上线轮询调度
3. 上线工作区级逻辑快照包
4. 接通 COS 产物存储与本地下载

交付：

1. `GET/PUT /backups/policy`
2. 自动备份任务链路
3. 成功作业下载

### Phase 2：恢复 dry-run

目标：

1. 上线从成功作业恢复的 dry-run
2. 上线恢复报告列表
3. 明确 include/exclude 数据域与用户映射报告

### Phase 3：恢复 apply 到新工作区

目标：

1. 上线正式恢复
2. 支持上传本地备份包后恢复
3. 完成端到端演练

### Phase 4：稳定性与运维完善

目标：

1. 告警与指标
2. stale job 自动补偿
3. retention 清理
4. 大工作区压测与文档固化

## Given-When-Then 验收样例

### ACC-WBR-005

1. Given：存在一份成功的工作区级备份作业
2. When：管理员发起 dry-run
3. Then：
   - 创建 `backup_restores`
   - 返回数据域统计、用户映射与警告信息
   - 不生成新工作区

### ACC-WBR-006

1. Given：同一来源包已有成功 dry-run
2. When：管理员发起 apply
3. Then：
   - 生成新工作区
   - 原工作区数据不变
   - 恢复记录写入 `targetWorkspaceId`

## 上线顺序

1. 数据库迁移先行
2. 后端接口与 worker 上线
3. 前端页面灰度显示策略卡片
4. 开启自动调度
5. 开启恢复 dry-run
6. 开启恢复 apply

## 灰度策略

### 开关维度

1. `workspace_backup_policy_enabled`
2. `workspace_backup_restore_enabled`
3. `workspace_backup_upload_restore_enabled`

### 放量节奏

1. 内部工作区验证
2. 小规模自托管试点
3. 全量开放备份策略
4. 通过至少 3 次恢复演练后再开放 apply

## 回滚策略

### 回滚目标

1. 任意时刻都可以关闭“恢复”能力，而不影响已生成的备份产物与作业查询。
2. 任意时刻都可以关闭“自动调度”，退回到手动备份。

### 回滚步骤

1. 关闭 `workspace_backup_restore_enabled`
2. 停止新的恢复任务入队
3. 观察正在运行恢复任务，自然结束或人工终止
4. 如需继续回滚：
   - 关闭 `workspace_backup_policy_enabled`
   - 停止调度扫描
5. 保留数据表、产物与历史记录，禁止破坏性回退数据库结构

### 不允许的回滚动作

1. 不允许删除已成功备份产物作为“回滚”手段
2. 不允许为了回滚恢复入口而强行改写历史 `backup_jobs` 状态

## 监控指标

1. `backup_job_total{status}`
2. `backup_job_duration_seconds`
3. `backup_last_success_timestamp`
4. `backup_restore_total{mode,status}`
5. `backup_restore_duration_seconds`
6. `backup_artifact_size_bytes`

## 发布门槛

1. 自动备份连续 7 天稳定运行
2. 至少 3 次恢复演练通过
3. COS 下载成功率 `100%`
4. 关键权限与安全测试通过
