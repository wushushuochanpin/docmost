## 备份任务状态机

### 状态定义

| 状态 | 含义 |
| --- | --- |
| `pending` | 任务已创建，尚未被 worker 执行 |
| `running` | 任务正在导出数据、打包或上传 |
| `success` | 任务完成，产物可下载 / 可恢复 |
| `failed` | 任务失败，需展示错误摘要 |
| `canceled` | 任务被取消或被系统补偿终止 |

### 流转规则

```mermaid
stateDiagram-v2
  [*] --> pending
  pending --> running
  pending --> canceled
  running --> success
  running --> failed
  running --> canceled
```

### 关键约束

1. `pending/running` 状态的任务在 stale threshold 后必须被补偿为 `failed` 或 `canceled`。
2. `success` 任务才允许下载与恢复。

## 恢复任务状态机

### 状态定义

| 状态 | 含义 |
| --- | --- |
| `pending` | 恢复任务已创建，等待处理 |
| `running` | 正在做 dry-run 或 apply |
| `success` | dry-run 或 apply 成功 |
| `failed` | 校验或恢复执行失败 |

### 流转规则

```mermaid
stateDiagram-v2
  [*] --> pending
  pending --> running
  running --> success
  running --> failed
```

### 模式约束

1. `mode=dry-run`：不落正式业务数据，只输出报告。
2. `mode=apply`：必须依赖同源成功 dry-run。

## 策略状态

| 状态 | 含义 |
| --- | --- |
| `enabled=true` | 策略参与调度扫描 |
| `enabled=false` | 策略存在但不参与调度 |

附加时钟字段：

1. `lastRunAt`
2. `lastSuccessAt`
3. `lastFailureAt`
4. `nextRunAt`

## 自动备份时序

```mermaid
sequenceDiagram
  participant Scheduler as BackupSchedulerService
  participant DB as backup_policies
  participant Queue as Backup Queue
  participant Worker as Backup Processor
  participant Artifact as BackupArtifactService
  participant COS as Tencent COS

  Scheduler->>DB: 查询 enabled 且 nextRunAt <= now 的策略
  Scheduler->>Scheduler: 获取分布式锁
  Scheduler->>Queue: 创建 schedule 类型 job(pending)
  Worker->>Queue: 消费 job
  Worker->>Worker: workspace 级互斥校验
  Worker->>DB: job -> running
  Worker->>Worker: 导出逻辑快照并计算 checksum
  Worker->>Artifact: 上传产物
  Artifact->>COS: 写入对象
  Worker->>DB: 写 artifactPath/checksum/summary
  Worker->>DB: job -> success / failed
  Worker->>DB: 更新策略 lastRunAt/nextRunAt
```

## 手动备份时序

```mermaid
sequenceDiagram
  participant UI as Backup Page
  participant API as BackupController
  participant Queue as Backup Queue
  participant Worker as Backup Processor

  UI->>API: POST /backups/jobs/run
  API->>API: 权限校验
  API->>Queue: 创建 manual 类型 job(pending)
  API-->>UI: 返回 job 摘要
  Worker->>Worker: 执行与自动备份相同链路
```

## dry-run 恢复时序

```mermaid
sequenceDiagram
  participant UI as Restore Drawer
  participant API as BackupController
  participant Queue as Restore Queue
  participant Worker as Restore Worker
  participant Artifact as BackupArtifactService

  UI->>API: POST /backups/restores(mode=dry-run)
  API->>API: 校验来源与权限
  API->>Queue: 创建 restore(pending)
  Worker->>Artifact: 读取 job 产物或 upload 包
  Worker->>Worker: 校验 manifest/checksum/schema
  Worker->>Worker: 生成目标工作区名冲突检查与用户映射报告
  Worker->>API: 写 report, status=success/failed
```

## apply 恢复时序

```mermaid
sequenceDiagram
  participant UI as Restore Drawer
  participant API as BackupController
  participant Queue as Restore Queue
  participant Worker as Restore Worker
  participant DB as PostgreSQL
  participant COS as Tencent COS

  UI->>API: POST /backups/restores(mode=apply)
  API->>API: 检查成功 dry-run 是否存在
  API->>Queue: 创建 apply restore
  Worker->>DB: 创建新工作区壳层
  Worker->>Worker: 生成 sourceId -> targetId 映射
  Worker->>DB: 写 spaces/pages/comments/backlinks 元数据
  Worker->>COS: 复制/写入恢复后的附件对象
  Worker->>DB: 写 attachments 元数据与 page_history
  Worker->>DB: status=success, report.targetWorkspaceId=...
```

## 失败场景与状态约束

| 场景 | 规则 |
| --- | --- |
| 调度重复扫描同一策略 | 必须由锁与幂等 job key 去重 |
| 备份上传失败 | job -> `failed`，不得残留“成功但无产物”状态 |
| 上传恢复包损坏 | restore -> `failed`，报告写明 checksum / manifest 错误 |
| apply 中途失败 | restore -> `failed`，目标工作区标记为恢复失败并进入人工处理清单 |

## 关键状态一致性要求

1. UI、API、数据库中的备份状态枚举必须一致。
2. 手动与自动任务只允许 `triggerType` 不同，状态机完全一致。
3. 恢复记录必须独立于备份作业列表，但可引用来源 `jobId`。
