## 未来阶段划分

### Phase 2：恢复体验增强

1. 支持恢复完成后自动引导进入新工作区
2. 支持更丰富的 dry-run 差异视图
3. 支持恢复后内容抽样比对报告

### Phase 3：身份与协作域增强

1. 评估恢复 `groups/group_users/space_members`
2. 评估恢复评论作者的更完整映射
3. 评估恢复 watchers / notifications

### Phase 4：高阶恢复能力

1. 评估“恢复到现有工作区”的受控模式
2. 若进入此阶段，必须补：
   - 停写窗口
   - 三方冲突检测
   - 原工作区回滚快照
   - 严格演练

### Phase 5：平台级灾备能力

1. 实例级整站备份
2. 平台级恢复演练
3. 无数据库记录时从 COS 直接发现可恢复产物

## 未来技术议题

### 1. 应用层加密

当前 V1 主要依赖 COS/S3 服务端加密。未来若安全要求提升，可评估：

1. 应用层 envelope encryption
2. KMS key rotation
3. 多 key 兼容解密

### 2. 增量备份

V1 全量备份更可靠、语义更简单。未来如工作区体量明显增长，可评估：

1. 增量文件对象快照
2. 内容域变化日志
3. 全量 + 增量组合恢复

风险：

1. 恢复复杂度显著上升
2. 包依赖链让自助恢复门槛变高

### 3. 直接 COS 历史浏览

未来可以评估在页面中列出 COS 指定 prefix 下的历史对象，但前提是：

1. 明确与作业记录的关系
2. 提供审计
3. 避免用户把外部未知对象当受支持备份格式

### 4. 原地恢复风险评估

这是最容易被需求再次提出的方向，必须提前记录风险：

1. 需要完整停写和锁表策略
2. 需要处理恢复过程中旧内容与新内容的冲突
3. 需要可逆回滚，不然一次误点就可能造成 P1 事故

结论：

V1 不进入此范围；未来若讨论，必须单独升级为高风险专题并重新过评审。

## 未来验收方向

1. 平台级实例灾备与工作区级自助恢复形成双轨能力
2. 更细粒度的数据域恢复
3. 更严格的合规与密钥治理

## 风险提醒

1. 若未来直接跳过 Phase 2/3 去做原地恢复，风险会高于当前专题至少一个数量级。
2. 若未来把工作区备份宣传成实例灾备，产品风险与运维风险都会被放大。
