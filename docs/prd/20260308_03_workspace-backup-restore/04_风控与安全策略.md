# 04 风控与安全策略

**成文日期**：2026-03-08 13:41:35 UTC+8
**最后修订**：2026-03-08 18:37:30 UTC+8

本文档用于定义权限、限流、审计与安全策略。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## 风控目标

1. 防止工作区级备份被误用为平台级灾备。
2. 防止误恢复覆盖线上生产工作区。
3. 防止备份包泄露导致内容外泄。
4. 防止调度重复执行、并发冲突或资源打满。

| --- | --- | --- | --- |
| 查看策略与作业 | 允许 | 禁止 | 禁止 |
| 保存策略 | 允许 | 禁止 | 禁止 |
| 手动触发备份 | 允许 | 禁止 | 禁止 |
| 下载备份包 | 允许 | 禁止 | 禁止 |
| 删除历史备份产物 | 允许 | 禁止 | 禁止 |
| 上传恢复包 | 允许 | 禁止 | 禁止 |
| 执行 dry-run | 允许 | 禁止 | 禁止 |
| 执行 apply 恢复 | 允许 | 禁止 | 禁止 |
| 查看恢复报告 | 允许 | 禁止 | 禁止 |

### 权限设计说明

1. 继续沿用“当前工作区设置管理权限”作为后端强校验。
2. 页面不提供工作区切换器，避免工作区权限与跨工作区运维权限混淆。
3. 即使未来存在 super-admin，总体仍应通过显式切换工作区上下文来操作，不在单页中批量跨租户执行。

## 高风险动作约束

### 1. 正式恢复

必须满足：

1. 来源包已通过同源 dry-run
2. 目标是新工作区，不得指向现有工作区
3. 二次确认文案明确展示：
   - 来源备份时间
   - 目标工作区名
   - “不会覆盖当前工作区”

### 2. 下载备份包

必须满足：

1. 仅成功任务可下载
2. 下载链接有短时效
3. 下载动作写操作日志 / 审计日志

### 3. 删除历史备份产物

必须满足：

1. 仅允许删除历史成功备份
2. 不允许删除最后一份可用成功备份
3. 不允许删除正在被恢复链路使用的备份
4. 删除动作保留审计记录，不移除 job 记录

### 4. 策略保存

必须满足：

1. 不允许自由 Cron
2. 只能选每日 / 每周 / 每月预设
3. 保留规则至少一个非空，避免无限增长

## 安全边界

### 1. 备份范围边界

1. 页面文案必须明确：
   - 这是工作区级逻辑备份
   - 不是整实例灾备
2. V1 明确排除：
   - 身份认证域
   - 分享链接状态
   - 商业与 License 域

### 2. 恢复边界

1. V1 只恢复到新工作区。
2. 原地覆盖恢复是二期高风险能力，不得通过隐藏参数或后门接口提前开放。
3. 恢复完成后，外部分享必须默认禁用，避免旧链接在新工作区“幽灵复活”。

### 3. 存储边界

1. COS 为推荐备份真源。
2. 本地下载只提供临时分发，不改变产物主存储语义。
3. 备份 prefix 必须独立于业务附件 prefix，避免误删。

## 产物安全

### 传输

1. 管理后台与 API 继续使用 TLS。
2. COS 下载链接使用签名 URL，限制有效期。

### 静态存储

1. V1 优先依赖 COS / S3 的服务端加密能力。
2. 若当前实例未启用 COS SSE/KMS，则必须在上线前给出风险提示。
3. V1 不承诺新增应用层加密；该能力放入未来阶段，避免空承诺。

### 完整性校验

1. 每个包必须生成 SHA256 校验和。
2. `backup_jobs.checksum` 必须落真实值。
3. dry-run 与 apply 都必须校验包完整性。

## 上传恢复包安全

1. 仅接受白名单扩展名：`.tar.gz`
2. 受上传大小上限限制
3. 解包必须在临时目录中执行
4. 路径遍历、zip-slip、目录逃逸必须被阻断
5. 清理过期上传包，避免长期堆积敏感文件

## 并发与资源风控

### 并发限制

1. 同一工作区同一时间最多 1 个备份任务
2. 同一工作区同一时间最多 1 个恢复任务
3. 全局恢复并发建议默认 `1`

### 资源控制

1. 调度器按分钟轮询，不做高频扫描
2. Worker 需支持大附件流式打包与流式上传
3. 对超大工作区设置任务超时与失败回收机制

## 日志与审计

### 必打字段

1. `workspaceId`
2. `jobId` / `restoreId`
3. `triggerType`
4. `operatorId`
5. `targetWorkspaceId`（恢复成功时）
6. `artifactPath`
7. `artifactDeletedAt`

### 审计事件

1. `backup.policy.updated`
2. `backup.job.started`
3. `backup.job.succeeded`
4. `backup.job.failed`
5. `backup.artifact.downloaded`
6. `backup.artifact.deleted`
7. `backup.restore.dry_run.started`
8. `backup.restore.dry_run.succeeded`
9. `backup.restore.apply.started`
10. `backup.restore.apply.succeeded`
11. `backup.restore.apply.failed`

## 告警规则

1. 连续 2 次自动备份失败触发高优先级告警
2. 已启用策略工作区 24 小时无成功备份触发告警
3. 恢复 dry-run 失败率突增触发告警
4. 恢复 apply 失败触发即时告警

## 风险清单与控制措施

| 风险 | 触发场景 | 风险等级 | 控制措施 |
| --- | --- | --- | --- |
| 工作区备份被误认为整站灾备 | 页面与文档描述不清 | high | 明确文案、范围说明、旧整库产物禁止恢复 |
| 误恢复覆盖生产数据 | apply 指向现有工作区 | high | V1 后端硬性禁止 |
| COS 权限错误导致上传失败 | IAM / endpoint 配置错误 | medium | 上线前连通性检查，失败时阻断启用 |
| 备份包泄露 | 下载链接长期有效或权限绕过 | high | 短时效签名 + 权限强校验 + 下载审计 |
| 调度重复执行 | 多实例同时扫描 | medium | 分布式锁 + 幂等 jobId |
| 超大包导致进程内存暴涨 | 使用 Buffer 聚合 | high | 全链路流式处理 |
