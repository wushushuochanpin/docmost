# 04 风控与安全策略

**成文日期**：2026-04-08 13:46:11 UTC+8
**最后修订**：2026-04-08 13:46:11 UTC+8

本文档用于定义权限、限流、审计与安全策略。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## 风控目标

1. 任何外部 AI 工具都不能突破现有页面/空间 ACL。
2. 首期外部 AI 调用必须默认只读。
3. Token 泄露、提示注入、爬取风暴、误写等高风险场景要有阻断与追踪方案。

## 权限策略

### 1. 工作区级开关

- `workspace.settings.ai.mcp = false`
  - 所有 `/mcp` 工具调用统一拒绝
- `workspace.settings.ai.search = false`
  - 可选择仅允许纯 FTS 或直接禁止语义召回

### 2. Token Scope 策略

- 首期默认 scope：`knowledge.read`
- 未显式授权的工具一律拒绝
- 写工具 scope 与只读 scope 严格分离

### 3. ACL 策略

1. `search` 返回前执行 ACL 过滤。
2. `fetch` 返回正文前再次执行 ACL 校验。
3. 不允许通过 `id` 猜测绕过 `search` 直接读正文。

## 限流与配额

### 建议阈值

| 维度 | 建议值 | 说明 |
| --- | --- | --- |
| 每 Token 每分钟 `search` | 30 | 防止高频探测 |
| 每 Token 每分钟 `fetch` | 60 | 防止批量抓取 |
| 并发连接数 | 5 | 防止单 Token 风暴 |

### 策略

1. 超额时返回 `MCP_RATE_LIMITED`。
2. 对明显异常模式记录告警：
   - 高频空查询
   - 按顺序枚举 `id`
   - 大量跨空间命中失败

## 审计策略

### 审计事件

1. `MCP_SEARCH_EXECUTED`
2. `MCP_FETCH_EXECUTED`
3. `MCP_SCOPE_DENIED`
4. `MCP_RATE_LIMITED`
5. `MCP_DISABLED_BLOCKED`

### 审计 metadata

- `tokenId`
- `toolName`
- `workspaceId`
- `userId`
- `queryHash` 或 `documentId`
- `resultCount`
- `clientIp`
- `durationMs`
- `decision`

## 提示注入与数据外泄风险

### 风险描述

1. AI 在读取私有知识后，可能把私有内容拼进后续公网搜索参数或第三方工具参数。
2. 即便 MCP 工具是只读的，也可能通过工具返回内容中的恶意指令影响模型后续行为。

### 控制策略

1. 首期建议把私有知识调用与公网搜索拆成两阶段，不在同一高权限会话中默认混用。
2. 只接入受信任的 MCP 服务，即仅连接本系统自身暴露的 `/mcp`。
3. 对工具输入参数做 schema 校验，不允许任意透传。
4. 对 `search` 结果中的 URL 与文档元数据做格式约束，避免把敏感数据拼进可点击链接。
5. 记录并审查工具调用轨迹。

## 写风险控制

1. 首期不开放写工具。
2. 后续写工具上线前，必须同时满足：
   - 独立 `knowledge.write` scope
   - 幂等机制
   - 明确审批/确认流
   - 更细粒度审计
   - 回滚与补偿方案

## 错误处理策略

| 场景 | 错误码 | 对外文案原则 |
| --- | --- | --- |
| 工作区未开启 | `MCP_DISABLED` | 明确提示联系管理员 |
| scope 不足 | `MCP_SCOPE_DENIED` | 不泄露内部能力细节 |
| 无页面权限 | `MCP_PAGE_FORBIDDEN` | 不暴露文档存在性细节 |
| 速率限制 | `MCP_RATE_LIMITED` | 提示退避重试 |
| 文档无效或已删除 | `MCP_DOCUMENT_NOT_FOUND` | 引导重新搜索 |

## 安全结论

本专题的安全边界是：

1. 首期只读。
2. 先检索后协议。
3. 先 Bearer 后 OAuth。
4. 先受信任私有知识，再考虑混合公网工具。
