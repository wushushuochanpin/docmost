# 09 未来实现草案

**成文日期**：2026-04-08 13:46:11 UTC+8
**最后修订**：2026-04-26 23:49:08 UTC+8

本文档用于记录后续阶段规划与边界。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

---

## Future Stage A：检索质量深化 + 图片内联支持

- 目标：
  - 完成 hybrid retrieval 默认上线
  - 引入更稳定的 rerank
  - 支持附件与评论分源召回
  - `fetch` 升级为 MCP `image` content block（base64），支持视觉型 AI 客户端在单次工具调用内直接理解图片，无需二次请求；超大图片（> 1MB）保留 URL fallback
- 依赖：
  - `page_embeddings` 元数据完善
  - 监控指标稳定
  - 确认主要目标 AI 客户端（Claude、Cursor 等）的 content block 兼容性

## Future Stage B：OAuth 与更细治理

- 目标：
  - 支持 OAuth 兼容的远程 MCP 授权
  - Token 与 OAuth 双模式共存
  - 完整 scope 策略
- 依赖：
  - 客户端兼容性确认
  - 授权与回调安全评审完成

## Future Stage C：可控写入

- 目标：
  - 开放 `create_page`、`update_page` 等写工具
  - 加入审批、确认与幂等
- 风险：
  - AI 误写
  - 越权与批量污染
- 前置条件：
  - `knowledge.write` scope 完成
  - 回滚补偿链路完成

## Future Stage D：多源知识与同步

- 目标：
  - 连接外部云盘、笔记或代码仓
  - 统一索引与统一权限编排
- 风险：
  - ACL 模型更复杂
  - 同步成本与存储成本上升

## 演进边界

1. 任何未来阶段都不能绕过现有权限体系。
2. 任何写能力都不能早于 scope、审批、审计和回滚闭环上线。
3. 不因兼容某单一 AI 平台而牺牲跨客户端可复用性。
4. 不默认整库、整树、全文或图片内联读取；范围扩展、全文读取和图片内联必须由 AI 基于用户意图显式请求，并受服务端上限约束。
