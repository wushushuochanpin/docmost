# 06 实施计划、测试与回滚

**成文日期**：2026-04-08 13:46:11 UTC+8
**最后修订**：2026-04-26 UTC+8

本文档用于定义实施阶段、测试矩阵与回滚方案。阅读时当前系统实现可能已发生变化，请以实际代码与产品行为为准，谨慎参考。

## 实施阶段

### Wave 1：只读 MVP

1. 实现 `/mcp` 入口与工具注册。
2. 实现 `search`、`fetch`。
3. 复用 Bearer Token 校验。
4. 对接审计与开关。

### Wave 1.1：检索质量增强 + 图片 URL 支持

1. 引入 hybrid retrieval。
2. 完善 snippet 与 citation 信息。
3. 增加限流与更多调用监控。
4. `fetch` 响应新增 `attachments[]`，返回页面内图片附件的 URL、MIME 类型与尺寸信息。

### Wave 2：治理增强

1. Token scope 语义化生效。
2. 工作区级配置与 Token UI 文案完善。
3. 审计字段扩展。

### Wave 3：写能力预备

1. 设计 OAuth 授权。
2. 评估写工具审批与幂等。
3. 仅在 scope、审计、回滚机制明确后再进入开发。

## 验收门槛

1. 所有 P0 用例通过。
2. 不出现越权读取。
3. 关闭开关后可以无损回退到“无 MCP”状态。
4. 纯 FTS 兜底路径在向量索引失败时仍可用。

## 灰度计划

1. 第 1 阶段：开发环境与单工作区自测。
2. 第 2 阶段：Owner/Admin 内测，只发只读 Token。
3. 第 3 阶段：开放给个人知识库场景的普通成员。

## 监控项

1. `/mcp search` QPS、P95、失败率
2. `/mcp fetch` QPS、P95、失败率
3. `MCP_SCOPE_DENIED` 次数
4. `MCP_RATE_LIMITED` 次数
5. Token 最近使用分布
6. embedding 任务失败数

## 回滚方案

### 回滚触发条件

1. 出现越权读取或疑似外泄事件
2. `search/fetch` 错误率持续超阈值
3. MCP 调用导致数据库或队列明显异常

### 回滚动作

1. 将 `workspace.settings.ai.mcp` 设为 false
2. 批量撤销受影响 Token
3. 将检索逻辑退回到纯 FTS
4. 保留审计日志与错误日志以供排查

### 回滚目标时长

- 平台级关闭：<= 10 分钟
- 单 Token 撤销：<= 1 分钟
- 检索策略回退：<= 30 分钟
