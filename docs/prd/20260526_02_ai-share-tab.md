# PRD: AI 分享 Tab

**版本**: 1.0  
**日期**: 2026-05-26  
**范围**: V1（纯前端，无新后端接口）

---

## 一、背景与目标

当前用户将文档分享给 AI 助手，需要手动：前往「账户设置→API Keys」创建 Token，再手动拼接 MCP URL + Token + 页面链接 + 提示词，操作割裂、易出错。

**目标**：在分享弹窗中增加「AI」标签页，一键生成 AI 可用的完整配置块（MCP URL + Token + 文档链接 + 操作提示词），降低接入门槛。

---

## 二、技术约束（影响设计的硬性限制）

| 约束 | 说明 |
|---|---|
| Token 仅创建时返回完整值 | `listPersonalTokens` 不返回 Token 明文，只有 `tokenPrefix`（前 12 位）。无法从列表中「选择并复制」。 |
| Token 为 workspace 级别 | 当前无页面粒度 scope，AI 拿到 Token 后可读整个工作区所有页面。 |
| MCP 必须工作区管理员开启 | `workspace.settings.ai.mcp !== true` 时 MCP 端点返回 403。 |
| EE 版 share modal 已有 Tabs | `page-share-modal.tsx` 已有 Access + Publish 两个 Tab，新增第三个 Tab 顺势而为。 |
| 社区版 share modal 无 Tabs | `share-modal.tsx` 使用 Popover + 单一面板结构，需单独处理。 |

---

## 三、用户故事

> 作为工作区成员，我想在文档分享菜单中一键生成「给 AI 用的配置」，复制后直接粘贴到 Claude / Dify / 其他 AI 工具，无需手动拼接。

---

## 四、功能入口

### 4.1 EE 版（page-share-modal.tsx）
在现有 `Access` / `Publish` Tabs 后增加第三个 Tab：

```
[访问权限]  [发布]  [AI 分享]   ← 新增
```

前提：仅当 `workspace.settings.ai.mcp === true` 时展示此 Tab。MCP 未开启时 Tab 显示但内容为「引导开启」状态（见 5.3）。

### 4.2 社区版（share-modal.tsx）
Popover 底部追加分隔线 + 「AI 分享」折叠区（`<Collapse>`），同样受 MCP 开关控制。

## 五、UI 状态设计

AI Tab 内部有三个状态，互斥展示：

### 状态 A：MCP 未开启
```
┌──────────────────────────────────────────┐
│  🔒 MCP 服务未启用                        │
│  请前往「工作区设置 → AI → MCP」开启后使用  │
│  [前往设置]                               │
└──────────────────────────────────────────┘
```
- 按钮跳转到 `/settings/ai` 并锚定 MCP 开关

---

### 状态 B：可生成 Token（初始状态 / 重新生成后）

```
┌──────────────────────────────────────────────────────┐
│ 分享给 AI                                             │
│                                                      │
│ 为此次 AI 接入生成一个专属 API Token                   │
│                                                      │
│ ┌─────────────────────────────────────────────────┐  │
│ │  包含子页面   ●──────────────────── ○            │  │
│ │  AI 可通过 list_pages 工具读取子页面             │  │
│ └─────────────────────────────────────────────────┘  │
│                                                      │
│ [ 生成 AI 专属 Token ]                               │
│                                                      │
│ ⚠ 该 Token 授予对整个工作区的读取权限               │
└──────────────────────────────────────────────────────┘
```

**「包含子页面」开关**（默认开启）：
- 开启：生成的提示词包含「请同时读取子页面」指令，并在 `list_pages` 调用参数中体现 `max_depth: 3`
- 关闭：提示词仅指向当前页面，AI 不主动读取子页面

**「生成 AI 专属 Token」按钮**：
- 调用 `createApiKey({ name: "AI - {page.title} - {YYYY-MM-DD}" })`
- 成功后进入状态 C

## 六、复制内容规格

### 6.1「复制 MCP 配置（JSON）」
适用于：Claude Desktop、Claude Code 的 `settings.json`

```json
{
  "mcpServers": {
    "docmost": {
      "type": "http",
      "url": "https://book.superchat.help/mcp",
      "headers": {
        "Authorization": "Bearer eyJhbGci..."
      }
    }
  }
}
```

> 不含页面链接——MCP config 是工具层配置，具体页面通过对话传递。

---

### 6.2「复制提示词」
适用于：直接对话的 AI 工具（Dify、Coze、ChatGPT Plugin 等）

**包含子页面 = 开启时：**
```
我已为你连接了 Docmost 知识库（通过 MCP 协议）。

MCP 服务：https://book.superchat.help/mcp
认证方式：Bearer Token（已在 MCP 配置中设置）

请执行以下操作：
1. 调用 get_page 工具读取此文档：
   https://book.superchat.help/s/general/p/untitled-xxx
2. 调用 list_pages 工具获取子页面（max_depth: 3），并按需读取相关内容
3. 基于以上内容回答我的问题
```

**包含子页面 = 关闭时：**
```
我已为你连接了 Docmost 知识库（通过 MCP 协议）。

MCP 服务：https://book.superchat.help/mcp
认证方式：Bearer Token（已在 MCP 配置中设置）

请执行以下操作：
1. 调用 get_page 工具读取此文档：
   https://book.superchat.help/s/general/p/untitled-xxx
2. 基于文档内容回答我的问题
```

---

### 6.3「一键复制完整配置」（主按钮）
合并以上两者，适合直接粘给会自己配置 MCP 的用户：

```
=== Docmost MCP 配置 ===
MCP URL:   https://book.superchat.help/mcp
API Token: eyJhbGci...
文档链接:   https://book.superchat.help/s/general/p/untitled-xxx
包含子页面: 是

=== 使用说明 ===
将 MCP URL 和 Token 配置到你的 AI 工具后，告诉 AI：
"请阅读这篇文档：https://book.superchat.help/s/general/p/untitled-xxx（含子页面）并回答我的问题。"
```

## 七、Token 生命周期说明（UI 展示要求）

| 场景 | 行为 |
|---|---|
| 首次打开 AI Tab | 进入状态 B |
| 点击「生成」成功 | 进入状态 C，Token 明文在内存中 |
| 关闭弹窗后重新打开 | 重置为状态 B（Token 明文已从内存清除，不可复原） |
| 点击「重新生成」 | 弹出确认框（"将创建新 Token，旧 Token 继续有效直到手动撤销"），确认后重新调用创建 API |
| Token 创建失败 | 状态 B 内显示 inline error，不进入状态 C |

---

## 八、安全提示（必须展示）

在状态 B 和状态 C 中均需展示：

> ⚠ **该 Token 授予对整个工作区所有页面的读取权限。** 请勿分享给不受信任的第三方。如需限制访问范围，请在 [API 设置] 中设置过期时间或创建完成后及时撤销。

---

## 九、不在 V1 范围内

| 功能 | 原因 | 计划版本 |
|---|---|---|
| 页面粒度 scope token | 需后端 scope 执行机制，工作量 1+ 周 | V2 |
| Token 自动过期设置（在此页面） | 创建 API 已支持 `expiresAt`，可 V2 在此 UI 加入 | V2 |
| include_children 的后端强制限制 | V1 的开关只影响提示词文本，无技术约束 | V2（scoped token 实现后） |
| Token 列表展示（此 Tab 内） | 无法从列表还原明文，展示价值低 | 不做 |
| 微信分享 AI 配置 | 超出场景 | 不做 |

## 十一、验收标准

1. **MCP 未开启时**：AI Tab 展示引导，按钮跳转正确
2. **生成 Token**：调用成功，Token 值正确填入三个字段
3. **复制 MCP 配置**：粘贴后为合法 JSON，`Authorization` 字段值正确
4. **复制提示词（含子页面）**：包含 `list_pages` 和 `max_depth: 3` 指令
5. **复制提示词（不含子页面）**：不包含 `list_pages` 指令
6. **一键复制完整配置**：包含三段内容（URL + Token + 链接 + 说明）
7. **关闭弹窗重新打开**：Token 字段清空，回到状态 B
8. **重新生成确认框**：出现确认提示，取消不创建新 Token
9. **Token 创建失败**：显示 error message，不进入状态 C
10. **安全提示**：状态 B 和 C 均可见
